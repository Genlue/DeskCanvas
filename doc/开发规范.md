# DeskCanvas 开发规范

> 适用于宿主、公共控件库、运行时、全部插件及相应检查程序。本文中的“必须”“禁止”是新增和修改代码的合入条件；“现状”说明已有实现，不代表允许继续复制历史写法。
>
> 核对日期：2026-10-29（新增第 5.1 节对话框外壳、图标居中规则与守卫规则 8/9）。配套阅读：[项目解析报告](项目解析报告.md)。文中源码路径相对仓库根目录。

## 1. 共同开发原则

**一个产品使用一套基础设施：通用外观由公共控件库提供，公共规则由宿主或共享服务执行，插件负责自己的业务。**

1. **先查找再实现。** 开工前检查 `DeskCanvas.UI`、宿主 `Services/`、`Views/Controls/`、`DeskCanvas.Runtime` 和 Core 接口。已有能力直接引用；能力不足优先扩展原实现。
2. **禁止复制基础设施。** 不得把另一个组件的按钮模板、面板壳、玻璃采样、主题判断、网络缓存、时间轮询或配置写入代码复制后改名。
3. **共性向共享层收敛。** 第二个消费者需要同一种能力时，必须检查是否应抽取；共享层通过属性、槽位、快照和委托接收差异，不认识具体插件类型。
4. **保留业务差异。** 天气图表、地图、字形时钟、清单编辑器可以拥有不同内容布局和业务色板；这不是另写标题栏、控件状态和存储系统的理由。
5. **迁移必须有真实消费者。** 同批完成共享实现、生产接线、旧重复实现删除和相关验证。为旧 DLL 保留的门面、资源别名和无会话路径必须登记，不能未经兼容验证删除。
6. **区分事实和目标。** 现有构造重载、兼容入口或测试辅助类型，不自动成为新组件模板。文档不得把“定义了接口”写成“已在生产统一接入”。
7. **行为变化要可审查。** 说明保存时机、刷新频率、数据作用域、视觉变化和释放方式；不在重构中顺手改变用户设置语义。

## 2. 模块归属与依赖

| 项目/目录 | 放什么 | 不放什么 |
|---|---|---|
| `DeskCanvas.Contracts` | 无 UI 的会话、活动状态、数据快照、调度和资源契约 | Avalonia、Win32、文件/网络的具体采集、插件类型 |
| `DeskCanvas.Core` | 插件 SDK、注册属性、布局与设置模型、Provider、程序集加载、Core 调度器 | 宿主/插件反向引用、Avalonia 控件、业务视觉实现 |
| `DeskCanvas.Runtime` | 会话实现、请求合并与 TTL、平台中立的数据提供器、时区解析、设置事务、资源账本 | 宿主/Core/UI 依赖、Avalonia/Windows 专属包、窗口操作 |
| `DeskCanvas.UI` | 通用 Avalonia 控件、模板、样式、设计 Token、面板和玻璃端口 | 宿主/Runtime/Core 依赖、插件业务、文件存储、平台采集 |
| `DeskCanvas` | 启动和 DI、Windows 适配、多屏、窗口、主题、材质、面板、配置方案、共享服务装配 | 对具体插件项目的静态引用、新增插件类型名分支 |
| `Widgets/<Name>` | 业务模型、ViewModel、视图、领域适配器、插件设置和本地化 | 其他插件的直接依赖、另一套公共控件和共享基础设施 |

当前编译边界：Contracts 无项目依赖；Runtime 和 UI 各自只引用 Contracts；Core 独立；宿主引用 Core、Runtime、UI。26 个插件目前都保留 Core 和宿主引用，部分直接引用 Runtime/UI。**不要把这描述成插件已完全脱离宿主。**

- 新共享契约优先放 Contracts；已有 SDK 契约保留其 Core 身份。跨层新增引用要先说明必要性并调整结构守卫，不能私自绕过边界。
- 插件按需要直接引用 UI/Runtime，沿用 `Private=false`、`ExcludeAssets=runtime`；不得新增插件到插件的 `ProjectReference`。
- 不新建平行的 `WidgetKit`、通用 `CommonControls`、第二个主题管理器或万能 `Utils`。已有公共控件入口就是 `DeskCanvas.UI`。
- 平台采集通过宿主或已存在的平台网关注入为普通 .NET 数据；不得向 Runtime 引入 SMTC、WMI、HWND 或 Skia 对象。
- 所有包版本统一写在 `Directory.Packages.props`；项目内 `PackageReference` 不另写 `Version`，不靠私带框架 DLL 解决冲突。

## 3. 公共 UI 的唯一入口

### 3.1 控件和样式选型

| 需求 | 必须复用 | 注意事项 |
|---|---|---|
| 标题、说明、编辑器组成的设置行 | `DeskCanvas.UI.Controls.Setting` | 使用 `LayoutMode`、`EditorMinWidth`、`EditorHorizontalAlignment` 适配宽度 |
| 设置行内部布局 | `SettingLayoutPanel` | 自定义组合使用既有槽位，不再写第二套宽度计算 |
| 滑块、百分比、可编辑小数 | `LabeledSlider` | `Value` 用于预览，`ValueCommitted` 用于完成提交 |
| RGB/ARGB 颜色输入 | `ColorInput` | 使用 `ColorFormat`、`AlphaPolicy`、提交事件；不复制解析和校验 |
| 圆形图标按钮 | `Button.dc-icon-button` | 可叠加 `compact`；工具提示与可访问名称须本地化 |
| 工具栏图标按钮 | `Button.dc-toolbar-button` | 可叠加 `compact`；复用 hover/pressed/focus/disabled |
| 操作按钮、分段选择 | `Button.dc-pill` | 用 `primary`、`ghost`、`active`、`capsule`、`compact` 表达变体 |
| 内层卡片 | `Border.dc-card-box` / `Border.dc-inner-card` | 复用填充、边框、内边距、圆角 |
| 状态徽标 | `Border.dc-badge` / `Border.dc-status-badge` | 状态需有文字，不能仅靠颜色 |
| 二级面板 | 共享 `SecondaryPanelShell` + 宿主 `SecondaryPanelWindow` | 宿主门面注入材质，详见第 5 节 |
| 对话框（确认/输入/选择器/编辑器） | 共享 `DeskCanvas.UI.Controls.DialogShell` + 宿主 `HostDialogWindow` | 透明窗口 + 卡片阴影留白，禁止 `AcrylicBlur`/`BorderOnly` 自建外壳，详见第 5.1 节 |
| 加载/正常/空/过期/错误状态 | `SharedStatusPresenter` | 它是状态呈现原语，不是自动生成界面的控件；业务注入本地化文案 |

`icon-btn`、`icon-button`、`pill-btn`、`card-box` 等旧类名是过渡别名。新 UI 使用 `dc-*`，不得在插件中重新定义这些基础选择器。

公共控件源码位于 `src/DeskCanvas.UI/Controls/`，公共样式入口为 `src/DeskCanvas.UI/Styles/Controls.axaml`。`src/DeskCanvas/Views/Controls/` 中的同名旧类型是兼容门面，不是可以独立修改的第二份实现。

### 3.2 引用方式

新页面直接声明：

```xml
xmlns:ui="using:DeskCanvas.UI.Controls"
xmlns:locales="clr-namespace:YourWidget.Locales"
```

以下为片段；`YourWidget` 和绑定属性需替换为本组件实际类型：

```xml
<ui:Setting Title="{x:Static locales:Locale.Widget_Opacity_Title}"
            LayoutMode="Auto"
            EditorHorizontalAlignment="Stretch">
    <ui:LabeledSlider Minimum="0" Maximum="100" Step="1"
                      Unit="%" Value="{Binding OpacityPercent}"
                      ShowEditableValue="True" />
</ui:Setting>
```

宿主已加载 `DeskCanvas.UI/Styles/Controls.axaml`，并通过旧 URI 门面合并共享 DesignTokens。普通插件不要再次加载整套 Fluent 或复制这些字典。独立样例/测试宿主需自行装配 Fluent、共享 Token 和实际需要的样式：

```xml
<!-- 放在 Application.Resources 下的 ResourceDictionary.MergedDictionaries 中 -->
<ResourceInclude Source="avares://DeskCanvas.UI/Styles/DesignTokens.axaml" />

<!-- 放在 Application.Styles 中 -->
<StyleInclude Source="avares://DeskCanvas.UI/Styles/Controls.axaml" />
```

公共控件中的 `AdminRequiredText`、`RestartRequiredText`、`InvalidFormatText`、`CloseButtonLabel` 等文案通过属性注入本地化资源。直接使用 UI 类型时不能指望宿主门面自动代填。

### 3.3 预览与提交

- 拖动中更新 `Value` 只用于预览；在 `ValueCommitted` 持久化。不要用每个属性变化事件触发一次磁盘写入。
- 模型载入、范围归一化和外部值同步不得伪装成“用户完成编辑”。
- 文本预编辑期间不得持久化半成品，不得因设置变化重建整个输入控件而丢失光标、焦点或 IME 状态。
- 需要保持编辑会话的视图实现 `IWidgetSelfRefreshing.Refresh(WidgetLayout)`，在原实例更新。
- 新公共控件需补 `UI/Samples/SharedComponentCatalog.cs` 或对应样例，以及真实 Avalonia 行为检查；只定义未使用的控件不算完成。

## 4. 视觉、主题与布局对齐

### 4.1 资源来源

几何和通用交互 Token 的源文件是 `src/DeskCanvas.UI/Styles/DesignTokens.axaml`；宿主 `Styles/DesignTokens.axaml` 为旧 URI 门面。材质、强调色、文本选区和业务语义色由宿主现有资源字典及主题服务提供。

| 语义 | 现有资源键（示例） |
|---|---|
| 设置行几何 | `SettingsRowPadding`、`SettingsRowGap`、`SettingsRowLabelMinWidth` |
| 页面与编辑器 | `SettingsPagePadding`、`ControlMinHeight`、`ControlNumericMinWidth` |
| 普通排版 | `FontSizeCaption`、`FontSizeBody`、`FontSizeTitle` |
| 图标按钮 | `IconButtonSize`、`IconButtonCompactSize` |
| 面板 | `SecondaryPanelCornerRadius`、`SecondaryPanelContentPadding` |
| 菜单/宿主表面 | `HostSurfaceCornerRadius`、`HostSurfaceBorderThickness` |
| 卡片/操作/徽标 | `CardSubtle*`、`Pill*`、`Badge*` |
| 控件交互 | `ControlHoverBrush`、`ControlPressedBrush`、`ControlFocusBorderBrush` |
| 组件正文外边距 | `WidgetContentHostMargin`（由宿主消费） |

规则：

- 使用 `DynamicResource` 跟随主题与窗口作用域变化。禁止在业务页面复制相同语义的颜色、圆角、间距和交互状态。
- 表格中的通配符表示资源族，不能直接当作 XAML 键使用；选用源文件中实际存在的键。
- 新语义若确有需要，集中新增 Token，并验证全部消费者。不要在插件里定义一个同名键覆盖全局来“修好自己的页面”。
- 业务图表、地图、天气色板和艺术数字可以有专属尺寸/颜色；须使用模块前缀并说明语义。不得为统一外观强行抹平业务差异。
- 圆形按钮半径、图形算法坐标等数学派生值不属于普通页面随意写圆角的许可；已有共享实现中的例外不扩散到业务代码。

### 4.2 视觉验收

新增或修改 UI 必须与相邻页面对齐，检查标题起点、编辑器基线、图标尺寸、行高、分组间距、卡片内边距、按钮状态和滚动方式。禁止用负 Margin、空格或空控件补齐可通过布局解决的误差。

- 设置行优先 `Auto` 自适应；窄空间转纵向，不截断主操作。按内容设置合理最小宽度，不依赖固定窗口宽度。
- 声明 `SettingsPage.ScrollOwnership="Host"` 的页面不能再包一个整页 `ScrollViewer`。长列表可有明确 `Height/MaxHeight` 的内部滚动。
- 组件外层间距、卡片、裁剪由 `WidgetContentHost` 和宿主负责；插件不要重复加一圈全局外边距或再次缩放整个根节点。
- 按格子跨度和 `SizeTiers` 切换内容档位；像素仅用于最终绘制。尺寸使用 DIP，原生窗口位置和捕获使用物理像素，边界处显式换算。
- 数字时钟、图表等业务字号可以专门设计；普通设置/面板正文优先用共享字号。语言变长时允许换行或调整布局。
- 检查简体中文与英文、浅色与深色、三种材质、可用的单色/强调色模式，以及 100%/150%/200% DPI。组件覆盖注册的跨度，面板检查内容溢出和小工作区。
- 截图必须注明主题、DPI、跨度/窗口尺寸和测试数据。截图只能证明对应环境，不替代原生窗口验证。

### 4.3 主题作用域

当前材质是 `Acrylic`、`LiquidGlass`、`FullColor`；`LiquidGlassV2` 和 `Colorful` 分别是别名，不是两种额外材质。

- 应用主题由 `ThemeService` 编排；统一主题投影使用 `ThemeProfileResolver` / `ResolvedThemeProfile`；不要在插件重写材质与颜色策略。
- 控件资源优先从自身/窗口作用域查找，C# 场景复用 `ThemeScopeResolver`；最后才回退应用资源。`DarkMode == null` 时读取所属窗口变体，不能把全局变体当成本屏结果。
- 二级面板通过 `PanelAppearanceResolver` / `PanelAppearanceBinder` 接收材质，不单独计算明暗或复制玻璃参数。
- 专属多彩卡片通过 `IWidgetSurfaceHints.ColorfulBackgroundResourceKey` 声明；宿主不得新增 `if (viewType.Name == "...")`。
- 玻璃统一走宿主 `LiquidGlassSurface`、共享壁纸源、调度和 GPU/CPU 回退链；插件不单独截屏、模糊或另写玻璃着色器。
- 文本选区消费 `Styles/InteractionResources.axaml` 中的成对资源，保证选区前景/背景一起变化。

### 4.4 图标体系

**全软件（宿主、公共控件库、Runtime、全部组件）禁止使用 emoji 或其他 Unicode 表意/装饰字符（✏️ 🗑️ 🔥 🏆 ✔ 之类）充当功能图标。** 按钮、状态、操作、徽标、占位等界面图标必须使用矢量 `Path`/`StreamGeometry`，优先复用 `dc-icon-button`、`dc-toolbar-button` 与共享卡片中的既有图形；自绘图形用 `Stretch="Uniform"` 加显式 Width/Height，由容器保证几何居中。

根因与背景：emoji 是文本字形而非图形——`Fill`/`Stroke` 等矢量属性不生效，无法跟随主题前景色（彩色/单色、明暗共 6 类作用域）；跨平台字体回退渲染不可控；行高、基线与字形内边距固定，无法与圆形/方形容器对中（Habits 二级面板编辑/删除按钮即因此错位）。选中态等前景反色同理：accent 底上的前景必须用 `AccentContrastForegroundBrush`，禁止硬编码 White/Black——黑白单色下 accent 极性随明暗翻转，硬编码必然白上白。

- 用户自选内容中的字符（如习惯条目的自定义图标字段及其种子数据）属于业务数据而非界面图标，不适用本条；其渲染容器仍须居中且明确省略/截断策略。Markdown 任务项勾选标记、发给 AI 的提示词文档正文同理属于内容。
- 新增代码一律禁止；2026-10-29 已完成存量清扫（宿主页 + 全部组件），守卫规则 9 阻止回潮：`src` 下 `.axaml`/`.cs`（去注释后）出现 emoji/dingbat 即失败，例外只能登记业务数据/内容渲染文件并写明理由。
- 充当图标的文本符号（✕、‹、›、+、-、↑、← 等箭头）不在本条禁令内，但仅限既有按钮沿用；新增按钮优先矢量图形。
- **矢量图标必须几何居中**：Avalonia 的 `Shape.Stretch` 只把几何缩放到自己的 `Bounds` 并对齐盒子**左上角**（没有居中选项），所以非正方形的图形放进正方形盒子会明显偏左（一个 14×20 的图钉放进 11×11 盒子偏左 1.65 DIP——「置顶图标不在圆形中央」即此）。规则：
  - 填充图形用 `GlyphGeometry.Square(...)` 包一层以**墨迹中心**为准的正方形画布（`DeskCanvas.UI.Controls`），再用正方形 `Path` 盒子或 `PathIcon`；
  - 描边图形不能被这层画布包（画布的对角线也会被描边），必须让自己的 `Bounds` 本身是正方形且以中心对称；
  - 通用图标放 `CommonGlyphs`，单一视图专用可内联；`UiFoundationChecks` 的 `CheckGlyphCentring` 会把每个图标渲染进 28 DIP 盒子实测墨迹中心，偏差 > 0.75 px 即失败。

## 5. 二级面板与窗口

**窗口根仍是 Window/对应派生窗口；其唯一业务外壳是共享 SecondaryPanelShell。不能把 Shell 当作 Window 的替代基类。**

1. 代码继承 `DeskCanvas.Views.SecondaryPanelWindow`，`InitializeComponent()` 后调用 `InitializePanel(cornerRadius)`。
2. Window 内容使用宿主门面 `DeskCanvas.Views.Controls.SecondaryPanelShell`，由它注入生产玻璃和外观。直接 UI 壳适用于独立组件库/测试及已显式提供外观的场景。
3. 通过 `Title`、`Subtitle`、`HeaderContent`、`HeaderActions`、`FooterContent` 和 `Content` 提供业务内容。关闭按钮、标题拖动区、玻璃和开合动效由共享壳与窗口基类管理。
4. 通过 `PanelService.Open(PanelRequest)` 打开，明确 `PanelKey`、owner 和 `PanelScope`。普通详情优先 `PerOwner`；确属进程单例的功能显式使用 `ProcessSingleton`。
5. 不能裸 `Show()` 绕过面板层级、冷却和 toggle 行为；不得在插件重复维护“当前面板”静态字典。
6. owner 关闭、屏幕变化和构造/显示失败后不能留下窗口、订阅或单例登记。不要释放由其他消费者拥有的 ViewModel。
7. 新窗口声明 `WindowRoles`；角色注册当前主要记录能力，仍需调用已存在的实际平台行为入口，不能假设注册自动设置 z-order 或激活策略。

禁止复制局部 `CardBorder`、`LiquidGlassSurfaceControl`、`PART_CloseButton` 外壳。业务内容中的内卡片可以保留，但必须复用公共样式。

### 5.1 对话框（`WindowRole.Dialog`）

**宿主内所有对话框只有一套外壳：`HostDialogWindow`（窗口）+ `DialogShell`（卡片）。**

1. 代码继承 `DeskCanvas.Views.HostDialogWindow`：它固定 `WindowDecorations=None`、`Background=Transparent`、`TransparencyLevelHint=Transparent`，并唯一一次注册 `WindowRole.Dialog`（`WindowRoles.Register` 不幂等，各弹窗自行注册会叠加 Opened/Closed 订阅）。
2. AXAML 根元素写 `<views:HostDialogWindow ...>`，内容根是 `<ui:DialogShell>`，用 `Title`/`Subtitle`/`HeaderContent`/`HeaderActions`/`Content`/`FooterContent` 提供业务内容；`ContentPadding` 只在该弹窗确有不同内边距时显式覆盖。
3. **不允许**在窗口上声明 `AcrylicBlur`（或 Mica/Blur）透明级别，也不允许 `ExtendClientAreaToDecorationsHint` + `WindowDecorations=BorderOnly`：前者把卡片放进一层毛玻璃窗口，卡片外会露出一圈毛玻璃；后者把标题区交给系统，`DialogShell` 的拖动手势收不到按键，窗口拖不动。卡片与桌面之间只能是 `DialogShell` 的**透明**阴影留白（`DialogShadowGutter`）。
4. 拖动沿用共享 `PanelDragBehavior`：标题条是拖动手柄，按钮/输入框/选择器/滑块自动排除；没有标题的消息型警告（`HasHeader=false`）由卡片本身承担拖动，保证仍可移动。
5. Escape 关闭走 `HostDialogWindow.OnDialogEscape()`；需要以特定结果关闭（`ShowDialog<T>` 的取消值）时重写它，不要再挂一个 KeyDown（基类先订阅，会抢先）。
6. 窗口尺寸按「卡片尺寸 + 2 × 阴影留白」取，避免留白吃掉内容；主题/圆角/前景由宿主样式 `Styles/Controls/DialogShell.axaml` 统一喂给外壳，弹窗里不写颜色。
7. `GridEditor` 仍是登记例外（全屏深色遮罩 + 固定浅色工具面板，表面契约相反），例外清单在 `scripts/check-ui-conventions.ps1` 的 `$DialogChromeExceptions`，必须带移除条件。

## 6. 共享数据：共享实例、共享键、明确所有权

### 6.1 使用入口

| 数据 | 生产入口/共享机制 | 边界 |
|---|---|---|
| 天气、空气质量、城市查询 | `SharedDataServices.Weather` → `OpenMeteoSharedProvider` | 现有天气适配器投影 JSON；`WeatherSharedDataProvider` 是另一层中立天气值封装，不替代完整响应 |
| 系统指标 | `SharedDataServices.SystemMetrics` → `SystemMetricsSharedProvider` | Windows 读取在宿主 `NativeSystemMetrics`，Runtime 只传值 |
| 存储卷 | `SharedDataServices.Storage` → `StorageDrivesSharedProvider` | 同一 TTL 内共用卷枚举，展示名称/百分比留给消费者 |
| 音乐会话 | `MediaManagerService` 的共享引擎 → `MediaSessionSharedProvider` | SMTC 平台网关在 Music，普通快照在 Runtime |
| 时区 | `SharedTimeZone.Resolve`（文件 `Runtime/TimeSource.cs`） | 这是时区解析缓存，不是全局时钟服务 |
| 新的跨组件读取 | `SharedDataProvider<TKey,TValue>` | 宿主装配唯一实例，领域适配器负责投影 |

**仅使用共享类还不够。每个视图 new 一个 Provider 仍会各自请求，必须让消费者使用同一个实例。**

### 6.2 数据使用规则

- 先列清已有消费者、来源、刷新频率和请求参数，再选共享入口；不得在视图里另开相同 HTTP/WMI/卷枚举轮询。
- Key 必须包含所有会影响结果的参数，如位置、单位、资源种类、语言；不要把 Owner/实例 ID 放进内容 Key，导致合并失效。
- 使用 `AcquireAsync(owner, key, cancellationToken)`，按真实提供器签名传参。Lease 用 `using` 或明确的替换/关闭流程释放，成功、失败、取消路径都要收尾。
- TTL 表示数据新鲜度，不能当作轮询定时器。视图刷新与提供器取数是两个责任。
- 使用 `DataSnapshot` 的版本、时间和新鲜度呈现加载、空、过期、错误和重试状态；失败不伪装成业务值 0。
- 保持“单个调用方取消只结束自己的等待”的语义；不要让一个组件关闭取消其他组件共享的请求。
- 网络 fetch 必须有提供器级超时/终止策略。当前通用引擎不会把调用方取消直接传给底层 fetch，不能只依赖视图 Token 来停止底层 I/O。
- 网络创建使用 `ProxySettings` 既有策略；后台处理结果回 UI 线程再更新 Avalonia 对象。
- 有副作用的播放控制、删除、剪贴板写入等命令不能用读取缓存合并，必须明确执行次数。
- 新共享源放平台中立逻辑到 Runtime，实际平台适配留在宿主/已有网关；补请求键、单飞、TTL、取消隔离和失败检查。

## 7. 会话、定时与资源释放

### 7.1 会话接入

有稳定 `InstanceId` 的桌面组件由 `WidgetFactory` 获取 `WidgetSessionRegistry` 中的会话，按构造参数注入 `IWidgetSession?`。普通插件不要自己注册全局会话。

- 有后台/定时工作时实现 `IWidgetActivityConsumer`，接收 `OnSessionActivity(ActivitySnapshot)`，根据 `PollingActive`、`RenderActive`、`DeadlineAllowed` 分别门控对应工作。
- 不应根据“窗口可见”推断所有业务均可运行；截止任务和绘制任务的活动条件不同。
- 会话当前主要负责记录活动；宿主还会向内容推送一次相同快照。只读 `session.Activity`、却不实现活动推送或主动对账，不能保证工作会自动暂停。
- 预览和部分 Legacy 路径无会话，这是受支持场景。预览无持久化写入、无不可回收的全局订阅；不能因 `session == null` 崩溃或向注册表漏登记。
- 重复 Attach/Start/Resume 不得重复订阅；Detach/Stop/Dispose 幂等。缓存设置页重新挂载时应能恢复。
- 离开作用域后取消任务、解除事件与文件监听；异步结果应用前核对实例、请求代次/Generation 和当前 Profile，丢弃过期回调。
- 关闭时不能仅依赖 GC。可重建的大缓存实现 `IWidgetSuspendable`，释放像素/渲染队列后由 `Resume` 重建。

### 7.2 当前可用的调度路径

仓库现有两套同名接口，不可混用：

| 类型 | 当前状态 | 使用要求 |
|---|---|---|
| `DeskCanvas.Services.TimerService` / `UpdateTimer` | 多数组件的生产共享节拍，宿主全屏时会 `PauseAll/ResumeAll` | 优先复用已有秒/分钟等节拍，结合活动门控成对 Subscribe/Unsubscribe |
| `DeskCanvas.Core.Scheduling.IWidgetScheduler` / `WidgetScheduler` | 已实现 owner 租约、暂停恢复、超时和统计；后台回调 | 需要此能力时显式装配生命周期，UI 回调需调度回 UI 线程 |
| `DeskCanvas.Contracts.IWidgetScheduler` | `WidgetScheduleRequest` 契约；当前 Core 调度器并未实现它 | 不能假定能从 DI 解析或自动替代 Core 接口；接入需真实适配与集成验证 |

- 禁止每个组件再建永久 Timer。不能复用现有路径时，记录任务类别、owner、暂停条件、重叠策略、超时和释放方式，并完善共享层。
- Core 调度器的可见性标签本身不会自动暂停任务；宿主必须显式门控/暂停 owner。
- 对 Core 调度器的 `Skip/QueueLatest/Allow` 等行为变更，必须用真实长回调验证；不能仅凭枚举名承诺并发语义。
- 业务倒计时按墙钟/截止时间对账，隐藏后恢复不能把遗漏 tick 当作未流逝时间。
- UI 过渡动画、局部防抖和已有媒体平台引擎可以保留特定机制，但必须有边界、取消/解除订阅和验证，不能扩展为另一套全局调度器。

### 7.3 缓存与账本

- 对昂贵的图片、壁纸、字形等缓存设定容量或像素预算，所有权和释放线程明确；不得以实例 ID 为无限缓存维度。
- 使用 `ResourceLedger.Instance.Report` 上报绝对数量与估算字节，释放后上报零；禁止把增量当作绝对量。
- 当前账本已接入部分玻璃、图片和字形路径；`MapTile`、`FileIcon` 等存在占位，不能宣称所有缓存都已观测。
- 压力阈值是实验参数，不能把 192/384/768 MiB 写成已冻结的跨设备性能标准；真机标定后再调整。
- 账本不是驱逐器，不负责自动 Dispose；报告失败不得影响业务。

## 8. 持久化、Profile 与身份

- 应用设置使用 `IAppSettingsProvider`；屏幕布局使用 `ILayoutProvider`；单组件设置通过 `IWidgetLayoutProvider`，业务数据通过现有 Store。
- 数据路径复用 `Const`，Profile 数据放 `Const.ActiveProfileFolder`。Profile 可热切换，Store 不得把当前路径永久固化到 static readonly 字段。
- 缓存和文件监听响应 `Const.ActiveProfileChanged` 重置/重绑；全局缓存、临时文件与用户业务数据作用域分开声明。
- 设置编辑需要草稿时复用 `PersistentSettingsSession<T>`；成功 durable save 后再发布完成事件，并处理 revision conflict/save failed。当前未全组件接入，迁移时保留明确的“实时/完成/确认保存”语义。
- 沿用 `JsonParser<T>` 的临时文件、flush、原子替换与保存失败不发布流程；不在业务 ViewModel 中直接 `File.WriteAllText` 覆盖正式设置。
- 新模型的默认值和 `Normalize` 共用同一常量，处理 NaN、Infinity、越界、缺字段和损坏输入。禁止未声明的破坏性字段/枚举重命名。
- 组件识别使用 `InstanceId` / `IndexOfIdentity`，不能使用跨 JSON 文档的 record Equals 判断是否同一组件。
- 更新已不存在的布局项不能顺手 append，防止删除或切换 Profile 后旧组件复活。

Profile 切换必须保持顺序：

```text
保存当前方案 → CloseAll（先解除旧窗口订阅）
→ 切换活动 Profile/通知 Store → Reload 设置与布局
→ 刷新显示器 → 应用主题/语言 → CreateFromLayout
```

导入、导出、解包和删除需验证最终路径仍在允许目录内；路径拼接使用 `Path.Combine`，不能信任文件名或 `..`。卸载默认保留用户数据，清理自启动时检查是否归属当前安装。

## 9. 代码、本地化与可访问性

- C# 类型/公开成员 PascalCase，局部变量/参数 camelCase；沿用所在文件命名和命名空间。视图、ViewModel、模型和服务各守职责，网络/存储逻辑不塞进 AXAML code-behind。
- 构造注入已有接口，避免在业务视图随处访问 `App.Services`；兼容门面中已有的定位器不能成为新增代码的默认模式。
- 所有面向用户的固定文案放英语/简体中文 resx，复用既有键；生成强类型资源时遵循项目既有生成方式。
- 图标按钮提供本地化 tooltip 和 `AutomationProperties.Name`；错误与选择状态不能只靠颜色；键盘焦点需可见。
- 正常取消不当作故障刷日志；失败需要可见状态或诊断，不用空 catch 隐藏关键保存错误。
- 日志不写令牌、代理密码、剪贴板原文和完整请求隐私。异步工作可追踪、可取消；避免 async void（框架事件处理除外）及 UI 线程同步等待网络。

## 11. 新增/修改组件交付清单

### 11.1 新项目接入顺序

1. 在 `src/Widgets/<Name>/` 创建同名 csproj，按功能相近且已使用共享入口的项目组织 `Models/ViewModels/Views/Services/Locales`；不整目录复制历史服务。
2. 目标框架按实际平台需求选择。通常输出到 `..\..\DeskCanvas\bin\$(Configuration)\$(TargetFramework)\Widgets`，设置 `AppendTargetFrameworkToOutputPath=false`；Windows 专属框架项目仍需对齐宿主 `net10.0\Widgets`，参照 Music/ControlCenter/Shortcuts，不能直接套用平台后缀。
3. 引用 Core 与必要的宿主/UI/Runtime，保持隔离元数据。Avalonia/Skia 共享包使用 `PrivateAssets=all` 和 `ExcludeAssets=runtime`，版本由中央文件控制。
4. 在 `AssemblyInfo.cs` 添加 `WidgetInfo`、`Locale` 和程序集版本；落实视图、可选设置模型/编辑视图、标题/说明键、默认跨度和预设跨度，标题键必须能从资源读取。
5. 使用既有构造注入路径，按是否有后台工作接入 Activity、刷新和释放；共享 Provider 在宿主/共享装配点建立，不能由视图逐个 new。
6. 将项目加入 `src/DeskCanvas.sln`，需要的新检查登记到 `tests/README.md`；正式公共门禁按影响同步接入验证脚本。
7. 验证 Debug 的实际 Widgets 输出和 Release 组件包。打包脚本会发现标准目录中的项目，但自动发现不能代替解决方案登记与运行时装载验证。

不得改变既有的 `FixedWidgets` / `StackWidgets` 等程序集标识，也不能把构建目录的 DLL 手工复制当作新增插件流程。

# DeskCanvas 项目结构与扩展指南

本文记录当前仓库已经存在的目录边界、插件接入方式和 UI 资源入口。它是维护约定，不会改变运行时行为；结构检查可用 `scripts/check-structure.ps1` 在本地或 CI 中只读执行。

## 目录边界

```text
DeskCanvas/
├─ src/
│  ├─ DeskCanvas/          宿主应用：启动、DI、窗口、设置页、全局主题
│  ├─ DeskCanvas.Core/     插件 SDK：模型、属性、接口、配置与布局服务
│  └─ Widgets/             可动态加载的插件项目（当前 17 个）
├─ scripts/                构建与只读维护脚本
├─ docs/                   架构说明、视觉实验记录、发布说明
├─ installer/              WiX 安装器输入
├─ tests/                  独立验证程序
└─ dist/                   本地构建产物（不作为源码输入）
```

宿主依赖 `DeskCanvas.Core`；插件依赖宿主提供的 Core、Avalonia 运行时和服务。插件项目通过 `Private=false` 与 `ExcludeAssets=runtime` 避免把宿主或框架副本复制进 `Widgets` 目录。不要从 Core 反向引用宿主，也不要让宿主项目直接引用某个具体插件；发现和激活由 `IAssemblyProvider`、`WidgetInfoAttribute` 和 `WidgetFactory` 完成。

每个插件目录至少包含：

* 与目录同名的 `.csproj`（`Fixed` 和 `Stack` 的程序集名分别是 `FixedWidgets`、`StackWidgets`，这是现有布局格式的一部分）；
* `AssemblyInfo.cs`，声明一个或多个 `WidgetInfo`，并通常声明 `Locale`；
* `Locales/Locale.resx`，以及需要生成的 `Locale.Designer.cs`；
* 按需使用 `Models/`、`ViewModels/`、`Views/`、`Services/`、`Assets/` 等子目录。

## 新增插件流程

1. 在 `src/Widgets/<Name>/` 创建 `<Name>.csproj`，目标框架和输出目录沿用现有插件项目；引用 `DeskCanvas.Core.csproj`，只有确实使用宿主公开类型时才引用 `DeskCanvas.csproj`，并保持运行时资产不复制。
2. 添加 `AssemblyInfo.cs`。每个可显示组件都要有 `WidgetInfo(ViewType, ModelType, EditModelViewType, titleKey, subtitleKey)`；插件菜单入口用 `Locale(LocaleType, displayName, svgPathData)` 注册。
3. 添加 `Locales/Locale.resx` 与 `Locale.Designer.cs`，并为需要的语言提供对应资源。资源键必须与 `WidgetInfo` 中的标题键一致。
4. 按既有组件约定组织 `Views/`、`Views/Settings/`、`ViewModels/`、`Models/` 和 `Services/`。组件的默认跨度、设置模型和视图类型由属性与模型决定，不要把插件类型硬编码到宿主。
5. 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\check-structure.ps1`，再按 `BUILDING.md` 编译宿主与插件。发布时由 `scripts/build-widgets-bundle.ps1` 将所有插件发布到扁平的 `Widgets` 目录；不要手工把 DLL 放入宿主项目。
6. 若插件新增了外部文件（字体、图片、SkSL 等），在插件 `.csproj` 明确声明 `AvaloniaResource` 或嵌入资源，并在本文档或插件说明中记录运行时读取路径。

## UI 资源入口

* `src/DeskCanvas/App.axaml`：Fluent 基础主题、全局控件样式、ContextMenu、滚动条和宿主内容边距合同；修改通用控件外观前先确认这里是否已有资源键。
* `src/DeskCanvas/Styles/`：按表面或主题拆分的资源字典（Accent、Solid、Transparent、LiquidGlass、Colorful、Monochrome 等）。新增颜色或圆角优先使用资源键，避免在页面中散落字面量。
* `src/DeskCanvas/Views/Controls/`：宿主复用控件；设置页页面位于 `src/DeskCanvas/Views/Pages/`（若页面属于宿主设置，勿放入插件）。
* `src/Widgets/<Name>/Views/`：插件自己的视图；`Settings/` 和 `Controls/` 只承载该插件专属 UI。插件应通过宿主提供的动态资源和控件契约保持卡片、二级面板、字体和间距一致。
* 图片、字体和着色器应放在实际消费它们的插件 `Assets/` 或 `Resources/` 下，并在项目文件中声明；视觉实验或对照截图放在 `docs/`，不要混入运行时资源目录。

## 安全与稳定性原则

* 插件加载依赖反射和可回收 `AssemblyLoadContext`，发布配置不得启用 trimming；插件输出不能携带另一份 Core 或 Avalonia 运行时。
* 单文件解包使用内容哈希决定是否更新，并对压缩包条目做路径穿越防护。任何新的解包、导入或文件复制逻辑都必须拒绝绝对路径和跳出目标目录的 `..` 路径。
* 配置文件来自用户可写目录。读取 JSON 时沿用现有 Normalize/迁移流程；写入时保持原子性和既有备份策略，不把用户数据当作程序集或可执行代码加载。
* 网络服务（天气、翻译、更新）应使用现有代理和超时设置，不在 UI 线程同步阻塞；错误应降级为可见状态或日志，不能因为远端响应异常导致宿主退出。
* 资源和文件路径优先使用 `Path.Combine` 与现有 `Const.DataFolder`/`WidgetsFolder`，不要拼接用户输入。日志中避免写入令牌、代理密码或完整隐私数据。
* UI 改动先复用现有 DynamicResource、主题字典和宿主内容边距规则，再新增资源键；不要在插件中复制整套 Fluent 主题。

## 维护检查

`Directory.Build.props` 提供隐式 using、可空引用与 Avalonia 编译绑定默认值；宿主、Core 和 `src/Widgets/<Name>` 源码项目关闭 SDK 自动程序集属性生成，只有标准插件目录启用动态加载。独立测试项目保留 SDK 程序集属性默认值。项目可以显式覆盖共享默认值，但应记录原因。`Directory.Packages.props` 统一包版本，项目中的 `PackageReference` 不写 `Version`；确需使用 NuGet 支持的 `VersionOverride` 时应说明兼容原因。

插件输出目录跟随宿主的配置和框架目录，并设置 `AppendTargetFrameworkToOutputPath=false`。`Music` 需要 Windows API，保留 Windows 目标框架，但仍输出到宿主的 `net8.0/Widgets` 目录。不要机械统一这类平台要求、程序集名或发布资源元数据。

### C# 常量与路径引用

应用展示名、文件选择器标题及由应用名组成的缓存或更新目录段复用 `DeskCanvas.Core.Const.AppName`；配置和布局主数据路径复用 `Const` 既有路径字段。设置模型已有 `Default*` 常量时，构造默认参数使用同类型的限定常量，`Normalize` 回退也引用同一常量，避免重复数值漂移。保留既有配置字段名称和值；序列化参数名、反射插件类型和程序集元数据属于兼容契约，不做机械重命名。

目录名统一不意味着目录生命周期统一：Map、Clipboard 和玻璃日志保留已有 LocalAppData 策略，更新文件保留 Temp 策略，便携主数据继续使用其原有数据目录。新增路径沿用对应功能的存储策略，不把所有缓存迁入 `Const.DataFolder`。

### 主题资源引用

`src/DeskCanvas/Styles/DesignTokens.axaml` 统一具有相同语义的 UI token，宿主页和插件视图优先复用这些资源与既有主题资源。`src/DeskCanvas/Services/ThemeResourceHelper.cs` 集中处理主题色资源写入、清理和样式切换，由 `ThemeService` 调用；它当前没有通用资源查询 API。菜单的托管圆角与原生窗口裁剪均读取 `HostSurfaceCornerRadius`，修改此资源时应验证两条路径保持一致。局部绘制参数、插件独有素材和兼容资源键应按实际用途保留。

新增或修改 token 后，检查实际 XAML 引用、主题切换、菜单与裁剪资源解析，可在本地运行：

```powershell
dotnet run --project tests/ThemeResourceChecks -c Debug
```

该程序目前覆盖 8 项主题资源检查。仓库既有 `.gitignore` 排除了 `/tests/`，因此它目前是本地验证程序，不能假定新检出的仓库或 CI 已包含这些检查。

仍需独立评估的默认值差异：`LiquidGlassV2Settings` 主构造函数的 `LiveSamplingInterval` 默认值为 `10ms`，而 `DefaultLiveSamplingInterval` 引用的常量为 `5ms`。本轮保留现有行为，后续明确采样与性能预期后再统一，避免在引用规范化时隐式改变默认配置。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check-structure.ps1
```

脚本只读取文件系统、项目 XML 和插件注册源码：成功返回退出码 `0`，发现边界或契约问题返回 `1`，参数、XML 解析或运行时错误返回 `2`。它检查宿主/Core 依赖方向、逐个插件引用的运行时隔离元数据、输出路径、共享运行时包的隔离，以及源码和测试项目的中央包版本声明；插件注册源码只做属性存在性检查，不能替代编译和运行时验证。脚本不会还原文件、运行构建或修改生成物，也不求值条件式 MSBuild 属性；需要确认最终属性时使用 `dotnet msbuild <project> -getProperty:<name>`。

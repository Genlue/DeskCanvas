# DeskCanvas 开发规范

本规范从 UI 冗余收敛工程（W0–W11，提交区间 `e77095e…f22a2f8`）中沉淀而来，是**强制要求**而非建议。目的：防止共享层已经建立、旧式写法继续生长的"冗余回流"。细则见 [UI-Foundation.md](UI-Foundation.md) 与 [项目结构与扩展指南](项目结构与扩展指南.md)。

---

## 1. 总原则

1. **先复用，再新建。** 动手前先查 `src/DeskCanvas/Styles/Controls/`、`src/DeskCanvas/Views/Controls/`、`src/DeskCanvas/Services/` 是否已有对应能力。没有才允许新建，新建的必须是"唯一实现"。
2. **接入与删除同批提交。** 把局部实现迁到共享层的那次提交里，必须同批删掉旧实现。禁止"新壳包旧壳"式假迁移。
3. **每批独立提交、独立可验证。** 一个工作包/一批改动 = 一个提交，构建 0 警告 0 错误 + 相关检查套件全过后才允许提交。
4. **不为减少行数牺牲业务差异。** 收敛的是通用外壳与规则；插件专属画刷、业务布局、特殊行为一律保留，并在提交信息里写明"留了什么、为什么"。

## 2. 目录边界与依赖方向

- `src/DeskCanvas.Core/`：模型与接口，**禁止引入 Avalonia/UI 类型**。跨宿主与插件的契约放这里。
- `src/DeskCanvas/`：宿主。共享样式（`Styles/`）、共享控件（`Views/Controls/`）、共享服务（`Services/`）。
- `src/Widgets/<组件>/`：插件。只允许依赖 Core 与宿主暴露的接口，禁止反向被依赖。
- UI 层接口（需要 Avalonia Control 的）放宿主 `Views/Controls/`，**不要放进 Core**（先例：`IWidgetOverlayProvider`）。

## 3. UI 强制规范（红线）

新增/修改代码时，以下红线由 `scripts/check-ui-conventions.ps1` 与 `tests/UiFoundationChecks/RedundancyGuardChecks` 自动把关，**FAIL 不允许提交**：

| # | 红线 | 正确做法 |
|---|------|----------|
| 1 | 插件内不得定义通用 `icon-btn`/`icon-button`、`group-header`/`section-header` 基础样式 | 用共享 `dc-icon-button` / `dc-toolbar-button` / `icon-button` / `dc-section-header` |
| 2 | 业务文件不得写死文本选区颜色 | 消费 `InteractionResources` 成对语义键；例外仅 GridEditor（局部成对资源） |
| 3 | 二级弹窗不得本地声明 `CardBorder`/`LiquidGlassSurfaceControl`/`PART_CloseButton` 外壳 | 根节点用 `SecondaryPanelShell`，标题/按钮走 Title/HeaderContent/HeaderActions 槽位 |
| 4 | 声明 `ScrollOwnership=Host` 的设置页不得保留整体根 `ScrollViewer` | 页内只允许带 MaxHeight/Height 的有界内部滚动区 |
| 5 | 禁止 `#AA808080` 哨兵灰回流；共享 UI 中数字圆角魔数须用语义 Token | 颜色/圆角一律取 `DesignTokens.axaml` 语义键 |
| 6 | 宿主 `Widget.axaml.cs` 不得出现插件类型名判断（Forecast/ProgressView 等） | 能力走可选接口（`IWidgetSurfaceHints` 等）；已知例外仅 MapView（行为查询） |
| 7 | 用户可见文案（Text/Content/Header/Watermark/ToolTip.Tip 及 C# UI 字符串）不得是裸字面量 | 进 `Locale.resx` + `Locale.zh-Hans.resx` + `Locale.Designer.cs`，XAML 用 `x:Static` |
| 8 | 不得绕过共享层"再写一份"同名能力 | 先改共享层，让所有消费者受益 |

**例外登记流程**：确认是真例外（业务差异/存量兼容）→ 在 `check-ui-conventions.ps1` 例外清单登记（每条带原因与移除条件）→ 若 `RedundancyGuardChecks` 有对应互验断言需同步 → 提交信息逐条列明。禁止为了过检改业务代码，也禁止改业务代码迁就过时断言（断言过时应修正断言并注释）。

## 4. 二级弹窗与插件兼容

- 新二级弹窗：继承 `SecondaryPanelWindow`，AXAML 根用 `SecondaryPanelShell`，构造函数调用 `InitializePanel(cornerRadius)`。材质、开合动画、Escape、失焦、外点关闭全部由基类接管，插件只写业务。
- 新能力契约必须是**可选接口**（默认接口实现或独立接口），不得在现有必需接口上加抽象成员——旧 DLL 不重新编译也要能装载。
- **兼容红线**：不改现有模型字段名、组件程序集名、视图类型名、已有布局存储标识。旧值反序列化安全忽略，不得抛错。
- 疑似旧 DLL 兼容问题：`RedundancyGuardChecks` 内置 3.5.0 基线装载验证逻辑，可复用其思路本地复现。
- `LegacyStackOverlayAdapter` 等兼容适配器：使用中，移除条件见代码注释，**不要提前删除**。

## 5. 检查与提交门槛

所有命令在仓库根执行。**门槛：全部相关套件 PASS 才能提交。**

```powershell
# 结构与规范（任何提交前）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-structure.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-ui-conventions.ps1
dotnet build .\src\DeskCanvas.sln -c Debug        # 0 警告 0 错误

# 按改动范围追加（dotnet run --project tests/<套件> -c Release）
```

| 改动范围 | 必跑套件 |
|----------|----------|
| 任何 UI/样式/弹窗/宿主 | `UiFoundationChecks` |
| 设置页/自适应布局 | `WidgetAdaptiveChecks`、`SettingsReleaseChecks` |
| 二级弹窗 | `UiFoundationChecks`（PopupMigration\* 段） |
| 宿主 Widget/Region/Stack/拖动 | `BottomBandChecks`*、`DragCommitChecks`、`MultiScreenGridChecks` |
| 主题/强调色 | `MonochromeAccentChecks` |
| 玻璃材质 | `LiquidGlassChecks` |
| 组件窗口关闭 / 配置切换释放（含 Folders 拖放注销） | `WidgetReleaseChecks`（真机：全组件类型关闭释放 + 切换配置释放共享材质缓存） |
| 搜索/Hitokoto/课表 | `SearchVisualChecks` / `HitokotoMemoryChecks` / `TimetableChecks` |

\* BottomBandChecks 有 2 条**预先存在**的 z-order 环境时序失败（基线即有，见 W11 提交说明），记录现状即可，不算新引入；若失败数变化则必须排查。

发布级改动追加：`dotnet build -c Release` + 组件包验证（组件引用不得复制宿主/Core/Avalonia DLL）。检查探针必须使用隔离的测试数据目录，禁止写入用户现有配置。

**注意**：`.gitignore` 含 `/tests/` 规则——新增测试文件提交时需要 `git add -f tests/<文件>`。

## 6. 提交信息与并行工作流

- 提交信息用仓库既有风格：`feat(W#)/fix(W#)/refactor(W#)/test/chore:` 开头，中文详述**改了什么、删了什么、留了什么、检查实证**（参照 `git log` 既有条目）。
- 大批次并行开发：用 `git worktree add -b wt-<批次>` 开独立工作树，**各批次文件零重叠**（检查套件每批只写自己的分部类 Check 文件，不动共享 `Program.cs`），完成后逐支 `--no-ff` 合并回 main 并全量回归。
- 不要 push 到 origin/upstream，除非用户明确要求。

## 7. 无头检查的边界（人工验收）

Avalonia.Headless 能覆盖算法、布局、模板、事件计数；以下必须真机验收，改动涉及时在提交信息中标注"待真机验收"：

- 真实 `BeginMoveDrag` 拖动、原生 Resize、DWM 玻璃/透明度；
- Win32 外部点击 hook、`SetWindowRgn` 原生 Region 裁剪、Acrylic 内移；
- 失焦宽限实测、DispatcherTimer 完成帧。

完整清单见 [UI-Foundation.md §5](UI-Foundation.md)。

## P4：真实设置持久化与主题发布

- `PersistentSettingsSession<T>` 与 `AppearanceSettingsSession` 接入真实设置 provider：保存成功后才推进 revision 和发布；失败保留草稿供重试，外部修改返回冲突，重新加载显式放弃草稿。
- 外观页 **19 个滑块**在编辑中暂存，在拖动完成、Enter 或失焦时提交，覆盖透明度、旧/新玻璃光学及文字阴影。字体保存也进入共同主题路径，并修复中文筛选清空字体的问题。
- ThemeService 和 LocaleService 改为持久化完成后的 `DataChanged` 发布，避免原子替换失败时显示未保存的主题或语言。
- `ThemeSettingsChecks` 通过 **14 项**；独立 `SettingsIntegrationChecks` 通过 **36/36**。集成检查使用真实页面、临时 JSON 文件和文件锁，验证原子替换失败、磁盘/缓存/资源不发布、临时文件清理、重试、冲突、Avalonia IME client 预编辑/中文输入/退格及两个 Window 的资源隔离。
- 迁移决策见 [ADR-P4](ADR-P4-theme-settings.md)。现有 uniform focus-theme 策略保留；双窗口资源隔离不代表每个物理屏幕已经能够独立选择主题。

## P5：共享天气与系统资源指标

- Weather/Fixed 的 forecast、AQI、geocoding 全部生产网络路径转向宿主进程共享 `OpenMeteoSharedProvider`；保留原公共兼容入口和丰富/简要模型投影，移除组件私有 HTTP 客户端和重复预报缓存。
- 通用 `SharedDataProvider` 提供请求单飞、成功完成后起算的 TTL、owner lease、取消隔离及统计。实际网络轮次读取当前代理设置，命中缓存或等待共享轮次时不新建客户端。
- `SystemMetricsSharedProvider` 共享 CPU/RAM/磁盘/网络/电池采集。Monitor 的 SingleMetric 与 MultiDashboard 为两个真实消费者；WMI 移入宿主平台边界，释放 collection/object。未改变 Shortcuts 系统操作或现有调度频率。
- `WeatherSharedChecks` 通过 **21 项**；独立 `ProviderIntegrationChecks` 通过 **15 项**，直接调用真实 Weather/Fixed/Monitor 入口，以冻结 JSON 和可控任务验证响应兼容、查询转义/count、单飞、取消/Dispose 隔离、可变模型隔离和共享指标，不访问外网或真实 WMI。
- 迁移决策见 [ADR-P5](ADR-P5-shared-weather.md)。其他共享数据源和长期指标压力验收继续后续推进。

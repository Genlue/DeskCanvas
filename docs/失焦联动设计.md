# 失焦自动切换设计（Auto switch on focus loss）

> 状态：已实现（v2.1）。设置默认关闭；旧配置文件（无 `FocusLink` 字段）自动视为未启用。

## 1. 功能概述

组件所在屏幕**没有应用窗口**（全部最小化/关闭）时为**聚焦**，使用「聚焦时」的主题；只要还有应用窗口占着屏幕就保持**失焦**——**点击桌面、任务栏、组件都不会改变判定**；把最后一个应用窗口最小化/关闭的瞬间，该屏**立即**切回聚焦（无延迟）。

- 每个状态可分别选择**主题**（材质：跟随应用主题 / 毛玻璃 / 纯色 / 液态玻璃 / 新液态玻璃 / 多彩）与**亮暗模式**（亮 / 暗 / 跟随系统 / 自动跟壁纸）。主题下拉与「应用主题」预设卡片同源（`ThemePresets.SurfaceTemplates` + `SurfaceNames.Of`），不会漂移。两个不同材质可以在不同屏幕上**同时显示**（逐窗口材质，多彩也不例外）。
- **材质覆盖会带上该材质自己的不透明度**（预设快照值）：纯色即不透明、液态玻璃保持轻盈，而不是沿用共享的不透明度——否则纯色会看起来和毛玻璃没区别。其余参数（强调色、玻璃参数、字体…）继续共享；「跟随应用主题」则全部沿用共享值。无边框时钟内的同款"跟随全局 + 全部主题"列表也消费这一份目录。
- 其余全部参数（强调色、不透明度、玻璃参数、字体等）两组共享，仍由「外观」页下半部分统一管理；材质选择只换材质，参数不跟着变。
- 判定方式可选：**各屏独立**（默认）／**全局统一**。
- 白名单进程不算应用（视为桌面家具）：它的窗口既不维持失焦、也不阻止聚焦。
- 功能相关设置全部位于「外观」页**「应用主题」区块上方**。

## 2. 判定规则

**判定的是“窗口存在性”，不是“点击归属”**（`FocusWatchService.ResolveUnfocusedScreens`，z 序遍历的纯函数）：

- 从窗口栈顶向下扫描（`EnumWindows` 的 z 序），对每块屏幕独立判定：屏幕上还有**非白名单应用窗口**（可见、未最小化）→ 该屏失焦；没有 → 该屏聚焦。
- 状态只在窗口真正出现/消失时变化：**点击桌面、任务栏、组件、任何窗口都不会改变判定**（“怎么点都是失焦”）；把最后一个应用窗口**最小化/关闭/隐藏**的瞬间，该屏**立即**切回聚焦——无驻留、无去抖（150ms 轮询 + `SetWinEventHook`（前台/最小化/恢复/显示/销毁/cloaked）即时触发）；应用窗口出现/恢复/移入某屏 → 该屏立即失焦。
- 不算“应用窗口”的：shell 表面（桌面 Progman/WorkerW、任务栏、开始菜单、任务视图 / Alt-Tab flyout，`Windows.UI.Core.CoreWindow` 仅当归属进程是真正的 shell 宿主）、**白名单进程**、**DeskCanvas 自己的全部窗口**（组件、面板、设置窗口——本应用对所有状态透明）、最小化 / 被 cloaked（虚拟桌面切换）/ 工具窗口（`WS_EX_TOOLWINDOW`）/ 无标题窗口。
- 窗口占用屏幕的重叠规则：与屏幕重叠 ≥ 窗口面积的 25%，或屏幕包含窗口中心 → 该屏计入；横跨两屏的窗口两屏一起失焦。
- **全局统一**模式：任意屏幕失焦 → 所有屏幕失焦。
- **全屏游戏挂起期间**（`FullscreenWatcherService` 判定被遮挡）延后结算，退出全屏时一次性应用；启动后 10 秒维持聚焦默认值（一次性，不变）。
- 「当前状态」行：失焦时显示“应用：主要应用”（z 序最上层的那个，点击不会使其跳动）；聚焦时显示真实前台（桌面 / 白名单进程 / 组件…）。

## 3. 数据模型

```csharp
// AppSettings.FocusLink : FocusLinkSettings?（null = 从未启用）
FocusLinkSettings {
    bool Enabled;                     // 默认 false
    FocusMode? Focused;               // 聚焦时亮暗模式
    FocusMode? Unfocused;             // 失焦时亮暗模式
    SurfaceStyle? FocusedSurface;     // 聚焦时主题（材质）；null = 跟随应用主题
    SurfaceStyle? UnfocusedSurface;   // 失焦时主题（材质）；null = 跟随应用主题
    string[]? Whitelist;              // 进程名（忽略大小写、容忍 .exe）
    FocusScope Scope;                 // PerScreen（默认）/ Global
}
FocusMode(bool? DarkMode, bool AutoTheme) // 与 Theme 的字段同构：
                                          // AutoTheme 优先；DarkMode=null 跟随系统
```

- 首次开启时两组默认承接当前主题（亮暗模式相同、材质跟随），视觉零变化；关闭时恢复启用前的行为，两组选择留档。
- `Theme` 本身**不被改动**：启用期间它仍是全部共享参数的载体；禁用后 `Theme.DarkMode/AutoTheme/Surface` 重新驱动全局。
- 多彩同样可以按状态选择：共享主题非多彩时，多彩调色板按窗口合并进该窗口的资源（见第 4 节），不会把 Fluent 资源键泄漏到其它材质的窗口。

## 4. 切换机制

- **应用自身 UI**（设置窗口、对话框）跟随「聚焦时」模式与共享材质（`ThemeService.EffectiveAppMode`）。
- **组件窗口/面板**：每个窗口携带自己的 `RequestedThemeVariant`，并按**自己的有效主题**渲染材质（`FocusThemeCoordinator.ResolveWindowTheme`），逐屏生效。
  - 亮暗之所以可行：样式资源本就是 `ThemeDictionaries`（Default/Dark 双字典），组件卡片背景、液态玻璃、二级面板都按「自己窗口的变体」取色并监听 `ActualThemeVariantChanged`。
  - 材质之所以可行：卡片画刷（`WidgetCardBackground`）、玻璃图层（`Widget.GlassMaterial` → `LiquidGlassSurface`）、原生模糊提示（`ApplyTransparencyHint`）、描边与文字透明度都按窗口解析；`ThemeService` 装载**两个状态涉及的材质字典并集**（连同玻璃采样管线），每个窗口只消费自己那份（卡片画刷已改为按有效主题计算，不再依赖全局资源）。有效主题 = 共享参数 + 状态亮暗 +（可选）材质**及其自带的不透明度**，「该窗口（变体、材质、不透明度）真正变化」时才刷新。
  - 状态变化时协调器通过 `IFocusThemedWindow` 唤醒窗口重解析材质（色调可能不变、只有材质变化）；自行解析配色的组件内容（Stack）通过 `IFocusThemedContent` 获得同样通知。
  - **多彩与颜色策略（ColorfulFixed 闭包与作用域隔离）**：
    - 当窗口有效主题为**多彩**（`EffectiveSurface == Colorful`）时，执行 **`ColorfulFixed`** 颜色策略：彻底忽略用户强调色（`AccentColor`）、单色模式（`Monochrome`）及透明度（固定 1.0）；由 `ColorfulResources.axaml` 独立提供 100% 封闭的 Fluent 控件（ToggleSwitch/CheckBox/RadioButton）交互状态色、卡片背景及所有组件语义色。退出多彩时完整保留并恢复用户既有的强调色与单色设置。
    - 当窗口有效主题为**普通材质**（毛玻璃/纯色/液态玻璃等）时，执行 **`Normal`** 策略：支持手选色与跟随系统强调色，支持三种单色模式（黑白/背景色/强调色）。
    - **窗口作用域严格隔离**：每次失焦状态切换等价于一次“手动切换到目标主题”。多彩与普通窗口互不串色、互不改写、互不污染。
    - **事务化清理与零泄漏**：进入多彩前彻底卸载单色样式、清除窗口级 Accent Ramp 覆写并挂载 `ColorfulResources.axaml`；退出多彩时彻底移除 `ColorfulResources.axaml` include，清理多彩标记并重新注入普通 Accent Ramp 与单色样式。连续切换 100 次字典与样式引用数量稳定为 0 或 1，无泄漏与累积。
    - **组件作用域安全查找（`ThemeScopeResolver`）**：组件颜色与画刷查找严格按「控件自身逻辑树 → 所在 Window 作用域 → Application.Current」逐级查找，严禁组件绕过窗口直接依赖全局 Application 资源，彻底避免多窗口共存或失焦切换时的组件串色。
  - 启用 → 赋值/覆盖；禁用 → 清空变体与窗口级资源（`null`，继承应用级），行为与没有此功能时完全一致。
- 触发源统一走 `FocusThemeCoordinator.Reapply()`：焦点状态变化、设置保存、壁纸变化（自动模式）、全屏恢复；组件/面板在打开时通过 `DesktopFurniture.Attach` 注册（弱引用跟踪，窗口关闭自动摘除）。

## 5. 页面（全部位于「外观」页，位于「应用主题」上方）

- **失焦自动切换**区块（置顶）：总开关（默认关）→ 判定方式 → 「聚焦时」「失焦时」两行（每行为 **主题 combo + 亮暗 combo**，附“多彩状态使用固定组件配色；普通状态继续使用外观页中的强调色和单色设置”说明）→ 白名单（chips + 「添加进程…」从**有可见窗口的运行中进程**里搜索勾选）→ 当前状态（只读：失焦时显示保持失焦的应用，聚焦时显示真实前台）。
- 「颜色」区的**亮暗模式**行：功能关闭时如常显示；启用后隐藏（由区块内的两组亮暗 combo 接管）。「应用主题」预设及颜色/参数区始终作为共享配置生效。
- 颜色控制项响应：在共享主题为多彩时，`AppearanceViewModel` 统一基于 `ThemeColorPolicy.Normal` 自动隐藏强调色、单色和背景色控制项。

## 7. 架构与设计约束

- 上下文菜单、工具提示等 `PopupRoot` 弹出层未单独跟踪，继承所属窗口/应用级变体。
- 判定与“点击”完全解耦：最小化/关闭才是“回到桌面”。一直可见的小工具窗口会维持失焦——把它加白名单或最小化即可；常开的浏览器窗口同理（这正是“有窗口=失焦”的语义）。
- DeskCanvas 自己的窗口（含设置窗口）对所有状态透明，不会钉住失焦——开着设置调参时在该屏能直接看到聚焦效果，要看失焦效果开个应用即可。
- 「跟随系统」模式在每屏独立下由 `ThemeVariant.Default` 直接接管，系统切换自动生效。
- **多彩与普通主题完全解耦并存**：设置窗口与对话框跟随聚焦时状态（聚焦为多彩时挂载完整多彩闭包；聚焦为普通时挂载普通样式与强调色）。组件窗口按各自屏幕独立应用状态主题，多彩与普通窗口并存时互不串色、互不影响。
- 文字透明度按窗口覆盖（毛玻璃 0.8，其余 1.0）；组件代码通过 `ThemeScopeResolver` 优先按 Visual 作用域查找资源，杜绝通过全局静态读取导致失焦切色异常。

# 临时文件中转站 · 设计提案

> 状态：**待评审**。以下默认值为我的推荐取值，未与用户确认的项在「待定」一节列明。

## 1. 目标与定位

在桌面上放一个**常驻的实体暂存篮**：把暂时不知道该放哪的文件先扔进去，等目标位置准备好，再直接从组件里拖出来搬走。

核心用户故事：

1. 桌面上堆了一堆截图/下载/微信收到的文件，先全部拖进篮子；
2. 打开目标文件夹（或聊天窗口、邮件）；
3. **鼠标在组件里按住某个文件直接往外拖**，落到目标位置，搬完篮子里就空了。

定位是「桌面的收件篮」，不是「又一个下载文件夹」，也不是 Dropover 那种跟在光标旁的悬浮货架。

## 2. 竞品调研结论

成熟方案的分歧点不在「能不能拖」，而在**暂存区出现在哪**。

| 产品 | 平台 | 暂存区位置 | 值得借鉴的点 |
|---|---|---|---|
| Yoink | macOS | 屏幕边缘 | 一开始拖拽就滑出细条，取空自动消失；一件事做十几年 |
| Dropover | macOS | 光标旁 | 拖到空货架弹出 Instant Actions（压缩/分享/上传）；多货架分类；货架可命名配色 |
| Unclutter | macOS | 顶部下拉 | 文件 + 剪贴板 + 笔记三栏抽屉 |
| Droppy | macOS | 刘海 | 把硬件既定地标当成投放点 |
| DropPoint | Win/Mac/Linux | 常驻置顶悬浮窗 | 多实例 + 计数角标；GPL-3.0 |
| Holdem | Windows | 光标旁 | Tauri 轻量，摇鼠标触发 |
| 拾放时 | Windows | 悬浮球 / 顶部吸附栏 | **只存路径引用不复制实体**；失效明确标记 + 可重新定位 |
| Fences | Windows 桌面层 | 桌面围栏 | 指定一个 Inbox 围栏当默认收件区——**与 DeskCanvas 同处桌面层，是最贴切的对照** |

**授权提醒**：DropPoint 为 GPL-3.0，与 DeskCanvas 的 CC BY-NC-SA 不兼容。只能借鉴交互，不得引入其代码。

## 3. DeskCanvas 的两个硬约束

这两条决定了我们不能照搬上面任何一家。

### 3.1 组件钉在桌面置底层

`WidgetZOrder` 把组件固定在桌面层，任何应用窗口打开都会盖住它。而中转站的主流程恰恰是「先开目标窗口，再拖出去」——两者直接冲突。

### 3.2 现有二级面板不承担这个职责

`SecondaryPanelWindow` 有两条规则让它不合适：

- **失焦 150ms 即关闭**（`DeactivateCloseGraceMs`），而拖出流程必然要点开目标窗口；
- `WidgetZOrder.PinPanelAboveWidgets` 只把它放到「组件层之上、普通应用窗口之下」，仍会被 Explorer 盖住。

### 3.3 解法：拖出瞬间临时提层

组件常态**仍在桌面置底层**，只在「文件正被拖出」的那一次临时提到最前，松手立刻还原。

可行性依据：拖出是我们自己发起的（`DragDrop.DoDragDrop`），可以在调用前提层、返回后还原，不需要全局钩子，也不留常驻置顶窗口。这样既保住了「桌面家具」的定位，又能把文件拖进任意窗口。

## 4. 形态定义

**桌面实体暂存篮**——一个绑死到全软件统一暂存目录的文件网格视图。

- 组件本体即投放区，也是取货区，**一直可见，不需要唤出**；
- 文件是**实体**搬进暂存目录，不是路径引用；
- 实现上 ≈ 一个绑定固定目录的 `BigFolder`，图标网格、监听、拖入拖出都可复用 Folders 插件现成能力。

## 5. 数据模型

### 5.1 统一暂存目录

新增 Core 层服务 `StagingDirectory`（不引入 Avalonia 类型，遵守开发规范 §2）：

- 默认路径：`%LocalAppData%\DeskCanvas\Staging`，即 `Path.Combine(Const.DefaultDataFolder, "Staging")`。
  **注意**：用 `DefaultDataFolder` 而非 `DataFolder`——后者可被 `dataFolder.json` 指针重定向到便携目录，暂存目录不该跟着搬。
- 用户可在设置里改成任意路径（例如 D 盘），指针文件沿用既有 `dataFolder.json` 的读写套路。
- 目录不存在时首次拖入自动创建；组件提供右键「打开暂存目录」。

### 5.2 组件设置模型 `DropZoneModel`

沿用 `BigFolderModel` 的形状，去掉目录选择，新增中转站专属字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `Columns` / `Rows` | int | 3 / 3 | 网格列行数，沿用 BigFolder 既有 `ResolveSpan` 逻辑 |
| `ItemSize` | double | 40 | 单格尺寸 |
| `ShowThumbnail` | bool | true | 图片是否渲染缩略图而非系统图标 |
| `SortBy` | enum | 加入时间 | 加入时间 / 名称 / 类型 |
| `DropAction` | enum | Move | Move / Copy，见 §6.1 |
| `RemoveAfterDragOut` | bool | true | 见 §6.3 |
| `StaleDays` | int | 7 | 停留超过该天数打「待清理」角标，0 = 关闭 |
| `MaxItems` | int | 0 | 上限，0 = 不限；超出时拒绝拖入并提示 |

### 5.3 需要持久化的运行时状态

放在组件的 `Settings` JSON 里（与其他组件一致），**不新建全局文件**：

- 每个暂存项的加入时间（用于 `StaleDays` 提示）；
- 上次打开的目录（若未来支持多货架）。

## 6. 交互规格

### 6.1 拖入

- **默认移动**：文件从原位搬进暂存目录，桌面立刻干净。
- 按住 `Ctrl` 拖入 = 复制一份进来，原文件不动。
- 同一次可拖入多个文件/文件夹；文件夹整体作为一个条目。
- 拖入过程中组件高亮描边（复用 `WidgetOleDropTarget` 的 `onDragActive` 回调）。
- 同名冲突：自动追加 ` (2)`，不弹窗打断。

### 6.2 暂存中的展示

- 图标网格（图片可选渲染缩略图），与 BigFolder 视觉一致；
- 卡片头部显示「N 项 · 总大小」；
- 空态显示「把文件拖到这里」提示；
- 停留超期的项打角标，卡片头部显示「M 项待清理」；
- 右键菜单：打开、打开所在目录、**打开暂存目录**、重命名、移除、清空全部。

### 6.3 拖出

- 鼠标按住条目直接往外拖，走 `CF_HDROP`，可落到任意接受文件拖放的窗口（Explorer、微信、浏览器上传框等）；
- 拖动开始时组件临时提到最前，松手后还原（§3.3）；
- **默认拖出即移出暂存区**（篮子空出格子），与「移动」语义自洽；
- 按住 `Ctrl` 拖出 = 复制，文件留在篮子里。

### 6.4 清理

- 「清空全部」需二次确认（文件是实体，删了就没了）；
- 停留超期只提示，不自动删除——自动删文件风险太高。

## 7. 技术方案

### 7.1 可直接复用的现成能力

| 能力 | 位置 | 说明 |
|---|---|---|
| 拖入（OLE + WM_DROPFILES 双路径） | `src/Widgets/Folders/Services/WidgetOleDropTarget.cs` | 直接引用，已有死亡句柄回收（`PruneDeadRegistrations`），别再写一份 |
| 文件网格与图标加载 | `src/Widgets/Folders/Views/BigFolder.axaml(.cs)`、`Services/FolderIconService.cs` | 视图骨架与设置项直接照搬 |
| 卡片圆角/材质/主题 | 宿主 `SecondaryPanelShell`、`PanelAppearanceResolver`、`DesignTokens.axaml` | 不新增样式 |
| 目录监听 | Folders 插件的文件监听实现 | 外部改动暂存目录时同步视图 |

### 7.2 需要新增的部分

1. **Core**：`StagingDirectory` 服务（路径解析、创建、容量统计）。不含 UI 类型。
2. **宿主**：`WidgetZOrder` 增加「临时提层 / 还原」能力，供插件的拖出路径调用。
3. **拖出**：Avalonia 11.1.3 的 `Avalonia.Win32.dll` 已含 `DoDragDrop` / `IDropSource` / `CF_HDROP` / `DragSource`，
   用 `DragDrop.DoDragDrop` + `DataObject.SetData(DataFormats.FileNames, paths)`。**需先写一个最小验证程序确认实机可用**，
   这是整个方案唯一未验证的技术前提。
4. **插件**：新建 `src/Widgets/DropZone/`，按 `项目结构与扩展指南.md` 的插件流程落地
   （`.csproj` / `AssemblyInfo.cs` / `Locales/Locale.resx` + `Locale.zh-Hans.resx` + `Locale.Designer.cs`）。
5. **文案**：所有用户可见字符串进 `Locale.resx`（开发规范 §3 红线 7，无裸字面量）。

### 7.3 命名

- 插件目录 / 程序集：`DropZone`
- 显示名：中转站（`DropZone_Title` / `DropZone_Subtitle`）
- 默认跨度：`2x2,4x2,4x4`（与 BigFolder 一致）

## 9. 待定

以下我按推荐值先定，需要确认：

1. **目录默认位置**：暂定 `%LocalAppData%\DeskCanvas\Staging`。若希望「桌面可见的真实文件夹」则改为桌面子目录，代价是桌面多一个图标。
2. **拖入默认动作**：暂定「一律移动，Ctrl = 复制」。备选是跟随 Windows 原生（同盘移动、跨盘复制）。
3. **拖出后是否保留**：暂定「移出暂存区」。备选是保留以支持反复投放到多处。
4. **全局服务的落地范围**：暂定「先只给中转站用，接口预留」。是否同时给宿主设置页加一个全局「暂存目录」配置区。
5. **是否需要多货架**：Dropover 的多货架分类很出彩，但会显著放大数据模型与设置页复杂度，建议二期。
6. **是否需要 Instant Actions**：拖到空篮子时弹出「压缩 / 打开方式 / 复制路径」之类动作。建议二期。
7. **是否与其他组件联动**：剪贴板存图、笔记附件是否也落到这个目录。建议二期。

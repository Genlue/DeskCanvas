> 阅读顺序建议：§1 结论 → §3 材质事实 → §4 内核 API → §5 聚焦搜索 → §6 其余落点 → §7 门禁。

## 1. 这次要做什么

把 Windhawk「Mac Island & Dock」的动效语言搬进 DeskCanvas，并且**在三种材质下都成立**：

| 材质 | 枚举 | 背景由谁画 |
|---|---|---|
| 亚克力 | `SurfaceStyle.Acrylic` | DWM（窗口级 backdrop） |
| 液态玻璃 | `SurfaceStyle.LiquidGlass` | 自己画（Skia，抓屏 + 折射） |
| 全彩 | `SurfaceStyle.FullColor` | 自己画（纯色/渐变填充） |

**核心要求**：动效参数（弹簧刚度、阻尼、时长、过冲预算）属于「材质无关层」，三种材质必须**手感一致**；只有「背景如何跟随形状」属于「材质层」，必须**分叉实现**。这条是本文所有方案的判据。

**重点**：聚焦搜索（Spotlight）是这套动效的样板间，必须先做对。它是唯一同时具备「形状 morph + 结果流式出现 + 高频唤出」的场景，做对它，其余界面照抄即可。

## 2. 已经做完的（不要重做）

### 2.1 动效内核

`src/DeskCanvas.UI/Animation/SpringMotion.cs`（新增，已进 API 基线）：

- **`Spring`**（struct）—— mod `SpringTowards` 的逐行移植：ω = 8 / seconds，**固定 1/480 s 子步积分**，settle 阈值 0.001 / 0.01，`SetTarget` 不打断速度。给「目标会中途改变」的动画用（悬停、拖拽、连续输入）。
- **`SpringMotion`**（static）—— 阻尼预设与 easing 工厂：
  - `Smooth = 1.0`（临界阻尼，不过冲）
  - `Bounce = 0.72`（mod 的 `kBounceDamping`，过冲 3.84%）
  - `Lively = 0.62`（mod 的 `kPanelWidthDamping`，过冲约 7.5%）
  - `CreateEasing(damping)` → `Avalonia.Animation.Easings.SpringEasing`

### 2.2 已经接上的界面

`src/DeskCanvas/Views/SecondaryPanelWindow.cs`：面板开合已从 M3 spline 换成弹簧。

- 开启缩放：`Bounce`；不透明度与关闭：`Smooth`。
- 玻璃仍由 `cardScale.PropertyChanged → SetAnimationFrameScale` 逐帧跟随，**没有改动共享端口**。

### 2.3 两条必须知道的结论（踩过的坑）

1. **Avalonia 12 的 `IEasing` 标了 `[NotClientImplementable]`，用户代码不能自己实现**。
   第一版写的 `class SpringEasing : IEasing` 直接编译失败。改用框架内置的
   `Avalonia.Animation.Easings.SpringEasing(mass, stiffness, damping, initialVelocity)`。
2. **参数映射**：`mass = 1`、`stiffness = 100`（ω = 10）、`damping = 20ζ`。
   ω = 10 让过冲峰落在进度 **45%**、末端残余 **0.1%**——与 mod 的形状一致，且末端不会留下需要"跳一下"的尾巴。
   已由 `tests/UiFoundationChecks/MotionChecks.cs` 的 13 条断言锁定（端点、过冲预算、积分器、60/240 Hz 一致性、重定向保速度）。

> 如果觉得面板的过冲太"弹"，把 `SpringMotion.Bounce` 换成 `SpringMotion.Smooth` 即可，一行。

**先感受一下再动手**：当前构建里，随便打开一个二级面板（天气 / 剪贴板 / 大文件夹）就能看到新的开合手感——卡片会在到位时轻微过冲再落定。这就是后面所有界面要对齐的"基准手感"。

## 3. 三种材质的物理事实（决定动效上限）

这一节是全文的地基。**不要试图用一套实现覆盖三种材质**，它们的几何来源根本不同。

| | 亚克力 Acrylic | 液态玻璃 LiquidGlass | 全彩 FullColor |
|---|---|---|---|
| 背景几何 | **HWND 矩形** | 卡片矩形（自己算） | 无背景 |
| 圆角怎么来 | `SetWindowRgn`（1-bit GDI） | Skia 抗锯齿 | Skia 抗锯齿 |
| 形状能否独立于窗口动 | **不能**（窗口不变，模糊就是满窗） | 能（每帧重算 optics） | 能（就是普通控件） |
| 改一次形状的代价 | 一次 win32k 窗口整形 + DWM 重采样 | 一次离屏重绘 | 一次重绘 |
| 圆角质量 | 硬切，动画中逐帧抖 | 平滑 | 平滑 |
| 代码里的开关 | `Theme.UsesNativeBlur`（`Theme.cs:114`） | `UsesRenderedGlass` | 都不走 |

### 3.1 结论：动效必须按材质分叉

- **液态玻璃 / 全彩**：背景是**视觉树内的东西**，形状怎么动它就怎么动。这是「正确」的架构，也是 mod 费了一个独立窗口才换来的性质。
- **亚克力**：背景是**窗口的属性**。任何"卡片在窗口内自己动"的动画，都会得到「模糊铺满整窗、卡片在里面动」——就是用户报告的「先出现一大块，遮罩再慢慢挪」。

现有代码里已经有两处"绕"，可以作为证据：

- `SecondaryPanelWindow.cs:188` `TransformAnimationEnabled => !UsesNativeBlurTheme()` —— 亚克力下**直接关掉缩放动画**。
- `SpotlightWindow.axaml.cs:1382` 起的唤出动画**没有**这层保护：`SurfaceRoot` 从 0.94 缩放到 1，而窗口已经是最终尺寸、区域也是最终卡片的区域。于是亚克力模式下唤出瞬间，卡片四周会有一圈 6% 的模糊光晕先铺开——同一个 bug 的轻量版。

### 3.2 所以：三种材质各自的"动效预算"

| 材质 | 允许的动效 | 禁止的动效 |
|---|---|---|
| 液态玻璃 | 形状 morph、缩放、圆角变化、透明度、内容 stagger | 无（成本除外，见 §7） |
| 全彩 | 同上，且最便宜 | 无 |
| 亚克力 | 位置移动、透明度、**窗口级**尺寸变化（窗口 = 形状） | 卡片在固定窗口内独立 scale / morph |

## 4. 动效内核 API 速查

### 4.1 用 easing（推荐，90% 的场景）

```csharp
new DoubleTransition {
    Property = ScaleTransform.ScaleXProperty,
    Duration = TimeSpan.FromMilliseconds(320),
    Easing = SpringMotion.CreateEasing(SpringMotion.Bounce),
}
```

- 跑在 Avalonia 的**渲染时钟**上，和合成同帧，不需要自己写循环。
- 任何监听该属性的东西（包括液态玻璃的 `SetAnimationFrameScale`）自动同相。
- 适合：开合、出现/消失、一次性形变。

### 4.2 用积分器（目标会变的时候）

```csharp
_spring.SetTarget(target);              // 中途改目标，速度保留
if (_spring.Step(dt, seconds: 0.32, damping: SpringMotion.Bounce)) { /* 还要下一帧 */ }
```

- 需要自己提供 `dt`，并**钳制**（内核已把单帧上限钳到 100 ms）。
- 适合：鼠标跟随、拖拽吸附、连续输入导致的尺寸变化、被中途打断的动画。
- 驱动方式：`TopLevel.RequestAnimationFrame(Action<TimeSpan>)` 自递归（一次一帧）。
  ⚠️ 该 API 在 headless 下是否被 `ForceRenderTimerTick` 驱动**尚未验证**；落地前先写一个 20 行探针确认，否则测试会挂死。

### 4.3 参数对照（mod 原值）

| 场景 | mod 常量 | 建议映射 |
|---|---|---|
| 岛展开 | `kOpenSeconds=0.42`，`kBounceDamping=0.72` | `Bounce`，时长 320–420 ms |
| 岛收起 | `kCloseSeconds=0.26`，阻尼 1.0 | `Smooth`，180–260 ms |
| 面板宽度 | `kPanelWidthSeconds=0.55`，`kPanelWidthDamping=0.62` | `Lively` |
| 出现/消失 | `kAppearSeconds=1.25` / `kDisappearSeconds=0.95` | 只用于淡入淡出，`Smooth` |

## 5. 聚焦搜索（重点）

### 5.1 现状（代码事实）

结构（`SpotlightWindow.axaml:373-378`）：

```
SurfaceRoot (Grid, RenderTransformOrigin=0.5,0.5)
├── GlassSurface (LiquidGlassSurface)   ← 仅液态玻璃可见
└── Card (Border, ClipToBounds)         ← 三种材质共用的填充/描边/裁剪
    └── CardColumns (结果列 | 竖线 | 预览列)
```

- 唤出：`PlaySummonAnimation`（`:1423`）——根节点 0.94 → 1 缩放 + 透明度 0 → 1，**180 ms `CubicEaseOut`**（`:117`、`:120`）。
- 收起：`Dismiss`（`:515`）——**瞬时**，注释写明「no exit animation」。
- 高度：`ApplyCardGeometry`（`:994`）直接 `Height = ...`。空查询时是 68 DIP 的**搜索条**（`:114`），有结果时**瞬间跳**到配置高度。
- 亚克力：`ApplyWindowRegion`（`:886`）按 `ClientSize` 切 1-bit 圆角；`RefreshWindowRegion`（`:913`）在每次 resize 重切。

### 5.2 目标动效（四段，按优先级）

1. **唤出**：不是"整块淡入 + 放大"，而是从**搜索条的真实位置**长出来。根节点缩放 0.94 → 1 保留，但换成 `Bounce`；透明度用 `Smooth`；同时给 `SurfaceRoot` 一个 6–8 DIP 的 Y 位移（自上而下落定），让"出现"有方向。
2. **搜索条 → 结果卡**（**这是重点中的重点**）：空查询是 68 DIP 的条，第一条结果到达时高度 morph 到目标高度，圆角同步变化。这是 mod 的"岛从一条线长成胶囊"，也是现在最生硬的一跳。
3. **结果流式出现**：结果列表按行 stagger（每行延迟 12–18 ms，总时长不超过 120 ms），透明度 + 4 DIP 上浮；选中高亮用 `Spring` 跟随（目标会随键盘连续变化，这正是积分器的用武之地）。
4. **收起**：反向 morph 回搜索条再淡出（160–200 ms），替换现在的瞬断。`Dismiss(reason)` 的四个调用点（热键 / 失焦 / Enter / Esc）语义不变，只是把 `Hide()` 推迟到动画结束。

### 5.3 分材质实现（关键）

**液态玻璃 / 全彩 —— 窗口不动，只动 Card**

- 窗口**保持目标高度不变**（`ApplyCardGeometry` 只改宽度，不改高度）。
- 高度动画作用在 `Card`（以及 `GlassSurface` 的 frame rect）上，用 `SpringMotion.CreateEasing`。
- 玻璃侧新增一个端口方法（见 §5.4），把「当前卡片的 rect + 圆角」喂进去，替代现在只能等比缩放的 `SetAnimationFrameScale`。
- 好处：**零窗口 resize**，没有 `SetWindowPos` 风暴，也没有 region 重切。

**亚克力 —— 窗口必须跟着动**

- 窗口高度 = 卡片高度，逐帧 `Height = ...`（Avalonia 会转成 `SetWindowPos`），`Resized` 里已有的 `RefreshWindowRegion` 负责重切区域。
- 代价：每帧一次 win32k 窗口整形 + 区域重算，在 4K/125% 下会掉帧。
- **推荐折中**：morph 期间**临时降级**为纯色卡片（把 `TransparencyLevelHint` 切到 `Transparent`、`Card` 用不透明填充），morph 结束（约 250 ms 后）再切回亚克力。视觉上是"卡片长出来之后玻璃才凝住"，比全程抖动好，也比关掉动画好。
- **不要**做的事：保持窗口最终尺寸、只缩 Card —— 那正是"先一大块"。

### 5.4 需要新增的端口方法

`src/DeskCanvas.UI/Controls/GlassSurfaceBase.cs` 目前只有：

```csharp
public abstract void SetAnimationFrameScale(double scale, Point anchorRelativeToSurface);
```

morph 需要矩形而不是等比缩放，建议扩展为（保留旧方法作为默认实现，避免一次性改所有调用方）：

```csharp
/// 当前动画帧里卡片覆盖的矩形（相对 surface 左上角）与圆角。
public virtual void SetAnimationFrameShape(Rect rect, double cornerRadius)
    => SetAnimationFrameScale(rect.Width / Bounds.Width, default);
```

宿主实现 `LiquidGlassSurface` 里把 `BuildAnimationFrame`（`:342`）从"按 `t` 缩放"改成"按 `rect` 定位"：`Width/Height/Radius/DesktopX/DesktopY` 全部由 rect 推导。**这是整个改造里唯一有技术风险的一处**，因为它决定了玻璃的采样原点是否还准。

### 5.5 改动清单（按顺序）

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `SpotlightWindow.axaml.cs:1423` | 唤出 easing 换 `Bounce`/`Smooth`，加 Y 位移 |
| 2 | `SpotlightWindow.axaml.cs:994` | 拆出 `ApplyCardGeometryInstant`（窗口尺寸）与 `AnimateCardGeometry`（Card 高度/圆角） |
| 3 | `SpotlightWindow.axaml` | `Card` 挂 `Height`/`CornerRadius` 的 `DoubleTransition`（按材质决定是否挂） |
| 4 | `GlassSurfaceBase.cs` / `LiquidGlassSurface.cs:325-354` | 新增 `SetAnimationFrameShape`，`BuildAnimationFrame` 改为按 rect |
| 5 | `SpotlightWindow.axaml.cs:515` | 收起改为反向 morph + 延迟 `Hide()`，用 `CancellationTokenSource` 防重入（现有 `summonAnimationCts` 可复用） |
| 6 | 结果列表 | 行 stagger（建议在 `ItemsControl` 的容器 `Loaded` 上做，不要用 `ItemContainerTheme` 的全局 transition，会波及所有列表） |

### 5.6 验收清单（必须逐条过）

- [ ] 三种材质下唤出动画**手感一致**（录屏逐帧对比，形状到位时间差 < 1 帧）。
- [ ] 液态玻璃：bar → card 全程玻璃**跟着卡片边缘走**，边缘不出现"先铺满后收缩"。
- [ ] 亚克力：morph 期间**没有**满窗模糊块；降级切换点不可见（无闪烁、无圆角跳变）。
- [ ] 全彩：morph 期间无重绘撕裂，圆角连续。
- [ ] 连按热键 5 次（快速开关）：不叠加动画、不残留半透明、不出现两个卡片。
- [ ] 输入即筛选（每敲一个字符）：列表不闪、选中行不跳、玻璃不重采样整屏。
- [ ] 收起：反向 morph 期间再按热键，能正确中断并重新唤出。
- [ ] 多屏 / 125% / 150% 缩放：morph 后卡片与窗口/区域对齐（无 1px 缝、无越界）。
- [ ] `MotionChecks` + `UiFoundationChecks` 全绿。

### 5.7 坑

1. **窗口高度是整数像素**。`Height` 动画会被逐帧取整，morph 时可能看到 1px 抖动；在 125% 缩放下尤其明显。液态玻璃/全彩方案（只动 Card）天然规避，亚克力方案要接受。
2. **`ApplyCardGeometry` 会改 `Position`**（宽度变化时左移 `delta` 保持居中）。morph 只改高度，不要顺带触发宽度分支。
3. **`Dismiss` 里释放了 `ScreenSnapshotProvider`**（`:542`）。改成延迟隐藏后，释放必须仍在真正隐藏之后，否则玻璃会拿到空快照。
4. **`summonAnimationCts` 是唯一的防重入闸**，收起动画也要挂在同一个 CTS 上，否则"收起中再唤出"会两个动画打架。
5. **玻璃每帧重绘有成本**：`LiquidGlassSurface` 在 `Bounds` 变化时会 `RequestRender`，morph 期间等于每帧一次离屏重绘。先量一下 4K 下的帧时间，必要时把 morph 期间的玻璃降到 30 Hz（`RequestRender` 有 debounce，可直接利用）。

## 6. 其余落点（聚焦搜索之后）

| 位置 | 现状 | 建议 |
|---|---|---|
| 面板开合 `SecondaryPanelWindow.cs` | ✅ 已用弹簧 | 保持；亚克力下仍是"关掉动画"，等 §3.1 的 GlassLayer 方案 |
| 组件 span 缩放 `Widget.axaml.cs:2032` | `Width/Height` 300 ms 线性 | 换 `Bounce`，但注意这是**窗口级** resize，亚克力下区域逐帧重切，先量帧时间 |
| 文件夹弹窗 4 个文件（`BigFolder/Folder/SingleFile/SingleLink`） | 固定时长 `DoubleTransition` | 统一换 `SpringMotion.CreateEasing`，时长 200–260 ms |
| 设置页 | 其余十余处 transition | 低优先；页面切换建议 180 ms `Smooth`，不要用 `Bounce`（大面积过冲会晕） |
| 组件悬停 / 选中 | 无动画或瞬变 | 用 `Spring` 积分器（目标会随鼠标快速变化），这是积分器的第一个真实用武之地 |

**统一原则**：小元素（图标、徽标、行高亮）可以 `Bounce`/`Lively`；大面板（面板、设置页、聚焦搜索卡片）只用 `Smooth` 或 `Bounce` 且时长 ≥ 240 ms。过冲是"弹性"，不是"果冻"。

## 8. 风险与未决

1. **亚克力的 morph 本质上是伪命题**。窗口级 blur 决定了"形状 = 窗口"。要么接受窗口逐帧 resize，要么 morph 期间降级（§5.3），要么走 `docs` 里讨论过的 GlassLayer 移植（独立 backdrop 窗口 + 组合树裁剪）。**建议：本期先做降级方案，GlassLayer 单独立项。**
2. **`TopLevel.RequestAnimationFrame` 在 headless 下未验证**（§4.2）。落地积分器前先探针。
3. **玻璃 morph 的采样原点**：`BuildAnimationFrame` 现在用 `animationAnchor` 推 `DesktopX/Y`，改成 rect 后必须保证采样原点仍是**桌面坐标**，否则 morph 时玻璃内容会"游"。这是最容易出错的一处，改完必须真机看。
4. **性能**：morph 期间玻璃每帧重绘；4K + 实时采样下需要实测，必要时降频。
5. **`Dismiss` 延迟隐藏**会改变"失焦即消失"的观感。如果产品上要求"点别处立刻没了"，收起动画只能做到 120 ms 以内。

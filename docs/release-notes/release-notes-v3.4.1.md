# DeskCanvas v3.4.1 更新日志

> 一个修复版本：自定义（手动）网格模式下**拖动组件松手后不再吸附落格**、要再点一下才进网格的问题——根因是 v3.4.0 引入的拖动提交协议里，Background 优先级的兜底提交任务会在拖动中途（鼠标停顿瞄准格子的那一刻，Win32 输入恰好静默）提前消费提交标志，真正的松手反而空手而归。现改为**原生移动循环自己宣布结束**（`WM_EXITSIZEMOVE`）时一次性提交，兜底只在循环从未进入时兜底。主程序升到 3.4.1，组件无变动，编译 0 警告 0 错误。

---

### 🖱️ 1. 修复：拖动松手不落格

* **现象**：手动网格模式下拖动组件、松开鼠标，组件留在松手处的原始位置，需要再点击一下才被吸进网格。
* **根因**：`BeginMoveDrag` 的原生移动循环是模态的，会泵消息；Avalonia 调度器对 Background（≤ Input）优先级任务的规则是「有挂起 Win32 输入就延迟、输入静默就执行」。v3.4.0 把松手提交改成了 `moveCommitPending` 一次性标志 + Background 兜底独占——于是拖动中途每次鼠标停顿（瞄准格子时的停顿正是如此），兜底任务就提前执行：消费标志、按中途位置吸附并存储；随后 `OnPointerReleased` 检查标志已清，**什么也不做**。旧实现之所以没暴露，是因为松开处理是无条件 `AfterMove()`，跑两次也无害。
* **修复**：提交协议改为三层，不变量是「**移动循环未结束时绝不提交，循环结束时必然提交**」——
  * **`WM_EXITSIZEMOVE` 拥有提交**（新）：Widget 窗口经 `Win32Properties.AddWndProcHookCallback` 挂原生消息钩子，`WM_ENTERSIZEMOVE` / `WM_EXITSIZEMOVE` 括住原生循环；退出消息由循环自己在窗口已停在最终落点时发出，此时一次性执行落格提交。钩子永不吞消息。
  * **兜底惰性**：`BeginMoveDragWithCommit` 仍按 Background 优先级投递兜底（覆盖从未进入原生循环的拖动），但循环激活期间它保持 inert，绝不消费标志。
  * **第三道网**：`OnPointerReleased` 保留标志门控提交，作为合成释放事件真的送达时的兜底（钩子正常提交后为空操作）。

### 🧪 2. 验证与版本

* 新增 `DragCommitChecks` 检查项目（真实 Widget + stub 服务，无头绑定生产钩子体驱动）：钩子不吞消息、循环括号置位/清位、**循环激活期 Background 派发后挂起提交幸存且零保存零吸附**（回归钉死）、`WM_EXITSIZEMOVE` 恰好提交一次（吸附 + 持久化 + 钩子/兜底双提交幂等）、从未进入循环的拖动由兜底提交。全绿。
* `WidgetAdaptiveChecks`、`LayoutOwnershipChecks` 等既有套件回归通过；全解决方案编译 0 警告 0 错误。
* 版本号：主程序 3.4.1（AssemblyInfo + Package.wxs 同步），组件本版无变动。

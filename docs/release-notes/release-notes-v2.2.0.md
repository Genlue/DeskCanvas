## uWidgetsPlus v2.2.0 更新日志

> 两大稳定性修复 + 屏幕身份加固：相册组件 GIF/动画 WebP「解出来但不动」的根因修复（网上常见的优化 GIF 从此真正播放）；远程控制（UU 远程等）断开后组件消失、再打开应用必崩的完整修复链；屏幕身份引入 EDID 硬件 ID 钉住 + 匿名屏防收留 + 孤立窗口自动拉回。

---

### 🖼 1. 相册组件 GIF / 动画 WebP 全帧播放修复（PictureImageLoader）

* **现象**：相册组件对全画布帧的 GIF 正常播放，但对**增量编码（delta）的 GIF——浏览器 / 表情包 / Giphy 等几乎所有来源的默认优化格式——动画完全静止在第一帧**：帧定时器在走、画面纹丝不动。
* **根因**：依赖帧（`RequiredFrame >= 0`，即只编码了与前一帧差异区域的帧）的解码分支直接把被依赖帧的像素当作当前帧输出，从未调用解码器——当前帧的增量内容被整体丢弃，N 帧解出来全是同一画面。实测一张 207 帧的表情包 GIF 解出 207 帧内容完全相同。
* **修复**：依赖帧解码改为「先种入被依赖帧像素，再由编解码器把当前帧脏矩形合成上去」（`SKCodecOptions(frameIndex, priorFrame)`）；与逐帧顺序合成的基准渲染**逐像素完全一致（0 差异）**，覆盖 Keep 链式 delta、RestorePrevious 回收语义、动画 WebP，RestoreBackground / 独立帧路径无回归；另修复保留帧拷贝列表未按帧号索引对齐的隐患。
* **测试基建**：压测夹具自带的 GIF 生成器 LZW 写码器本就不合规（码宽不随解码器字典增长，产出坏流）——已重写为规范写码器，并新增「delta 链逐帧像素断言」与「恢复背景语义断言」两类夹具，本类 bug 从此必被测试捕获。

### 🖥 2. 屏幕身份加固：远程虚拟屏不再「拐走」组件（DisplayMonitorService / ScreenMatcher）

* **现象**：UU 远程等远程控制创建的虚拟屏幕会**收留桌面组件**；断开远程后组件随虚拟屏幕一起消失，且 `layout.json` 里留下 `Screen|分辨率` 的幽灵条目（同名屏幕可反复收留）。
* **EDID 硬件 ID 钉住（ScreenLayout.HardwareId）**：每块显示器的 EDID 硬件 ID（如 `DELA0D2`）稳定跨接口 / 跨显卡 / 跨驱动重装。配置条目在首次匹配后自动回填硬件 ID，此后**只有那块物理显示器能匹配它**——同分辨率的虚拟屏、替身屏再也无法顶替；刷新时如条目名陈旧还会顺带修正（驱动更新导致的改名自愈）。
* **匿名屏防收留**：既无硬件 ID 又无真实名称的屏幕（远程工具虚拟屏、无身份的间接显示驱动）不再允许按名称 / 分辨率自动匹配任何配置条目——它们曾经共享同一个 `Screen|宽x高` 键，这正是组件被拐走的通道；仍支持手动绑定与硬件 ID 两种显式路径。
* **误配对收紧**：显示器数与屏幕数不一致时（远程会话拓扑抖动的典型状态）不再把「剩余的随便哪个设备」硬塞给屏幕——过去这会谎报屏幕身份并写进匹配键。
* **陈旧幽灵条目清理**：未被连接且其组件全部与已连接屏幕重复的旧式条目（GPU 适配器名键 / `Screen|` 键）自动从布局中清除；组件无处可寻的真实显示器条目一律保留。
* **孤立窗口自动拉回**：显示器消失时 Windows 会把窗口留在原地（可能落在已不存在的虚拟屏幕坐标上）。拓扑变化后，所有落在任何已连接屏幕之外的组件窗口自动吸附回自己的存储槽位；仍在屏上的组件位置分毫不动。

### 🪟 3. 托盘 / 二次启动崩溃修复：设置窗口永不真关闭（Settings）

* **现象**：远程会话期间组件窗口全部被拓扑变化关闭后关闭设置窗口，应用变成「僵尸」——托盘还在，但此后任何打开设置的路径（托盘点击、组件右键、**双击 exe 的二次启动移交**）都触发 `InvalidOperationException: Cannot re-show a closed window` 直接杀死整个进程。
* **根因**：共享设置窗口在「无组件存活」时被允许真关闭（注释假设关闭即退出应用），但不可见的锚点窗口让进程继续活着，DI 单例就此毒化。
* **修复**：设置窗口在应用存活期间一律只隐藏不关闭（真退出仅由托盘「退出」触发）；`ShowAndActivate` 对已关闭实例增加守卫；二次启动移交回调整体兜底，任何异常不再带崩进程。

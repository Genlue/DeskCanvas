## uWidgetsPlus v1.9.13 更新日志

> 修复 v1.9.12「背景清晰度」的**采样位置错位** —— 降低分辨率时壁纸会滑到桌面另一处，
> 卡片里显示的根本不是它背后那块壁纸。

### 🐞 问题

v1.9.12 引入背景清晰度后，任何低于 100% 的档位都会让采样位置偏移，且偏移量随卡片在桌面上的
位置增大而增大（右下角的组件偏得最厉害）。

### 🔍 根因：同一个缩放系数被乘了两次

卡片原点交给着色器时被**预乘了一次 `sourceScale`**，而着色器又把整个渲染像素和再乘一次：

```csharp
SourceOriginX: frame.DesktopX * sourceScale,   // 预乘
```
```glsl
float2 base = rxy - n * shift + srcOrigin;
sampleRgb(base * srcScale);                    // 又乘
```

得到的是 `rxy·s + DesktopX·s²`，而正确值应是 `rxy·s + DesktopX·s`。
**只有 `s = 1` 时两者相等** —— 而 v1.9.12 之前背景分辨率被硬编码为 2560，在 2560 宽桌面上
恰好算出 `s = 1.0`，所以这个单位错误一直潜伏，直到清晰度设置让 `s` 变成用户可选。

修复：原点按**渲染像素**原样传入，由着色器统一乘一次。

### 📏 为什么之前的对比测试没抓到

`GlassGpuProbe` 的同帧 GPU/CPU 逐像素对比此前用了一张**光滑的合成壁纸**（一片深绿加两个大圆），
50 px 的错位在那种图案上几乎不产生像素差异，所以它一直报告「平均 |Δ| 23」这种看起来正常的数字。

现在那张壁纸换成 **40 px 网格**：错位会立刻显形。同一套对比在修复前后的读数：

| 背景清晰度 | 修复前 平均 \|Δ\| | 修复后 平均 \|Δ\| | 修复前 GPU 中心 | 修复后 GPU 中心 |
|---|---|---|---|---|
| 100% | 32.9 | 32.9 | `#bdbfbe` 浅灰 ✓ | `#bdbfbe` 浅灰 ✓ |
| **50%** | **181.3** | **51.0** | **`#223629` 深绿 ✗** | `#b7bab8` 浅灰 ✓ |
| 25% | — | 79.5 | — | `#909792` ✓ |

修复后残余的差异随清晰度上升而增大，这是**分辨率降低本身的模糊**，不是位置错位 ——
三个档位的中心颜色都落在同一族（浅灰，与 CPU 的 `#d0d0d0` 一致）。

### 🛡 新增守卫

`LiquidGlassChecks` 增加三项断言，锁死「背景缩放不得移动采样原点」：
100% / 50% / 25% 三档的 `SourceOrigin` 必须完全一致；它必须等于卡片的桌面位置（渲染像素、未缩放）；
`SourceScale` 必须如实到达着色器。只要有人再把缩放乘错一次，测试立刻失败 ——
不再依赖「恰好 s = 1」这种巧合。

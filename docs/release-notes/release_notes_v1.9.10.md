## uWidgetsPlus v1.9.10 更新日志

> 核心是让 **GPU 液态玻璃真正跑起来**。v1.9.9 交付时它**从未在设备上画出过一帧**：自检判定
> 设备端编译失败后永久回退 CPU，于是着色器里的错误也无从暴露。本版修掉两处根因，让 GPU 路径
> 产出与 CPU 渲染器一致的画面，并解决了随之暴露的内存问题。

### ⚡ GPU 路径可用：Skia 内联器不再能悄悄废掉它

`sample(child, coord)` 会被 Skia 展开成对子 fragment-processor 链的调用，并以**入口点的**输入参数
`_input` 作实参——所以这个调用必须最终落在 `main` 里。一旦它留在一个**没有被内联**的函数中，
设备端程序就会引用不存在的 `_input`，**编译失败却不报错**，结果是一张**全透明卡片**。

用真机探针（`tests/GlassGpuProbe`，ANGLE/EGL 窗口 + 离屏读回）二分测出内联器的实际形状：

| 辅助函数形态 | 调用 1 次 | 多次 |
|---|---|---|
| 4 tap 双线性（多语句） | 内联 | **2 次即不内联 → 全透明** |
| 12 tap（多语句） | 内联 | **2 次即不内联 → 全透明** |
| 单次采样（1 tap） | 内联 | **40 次仍内联** |
| 含提前 `return` 且采样 | **不内联 → 全透明** | — |

原 `sampleRgb`（4 tap、被调用约 10 次）与 `sampleAura` 正落在失败区间。不再依赖这个启发式，
改为**构造上就安全**：所有采样用 `@fetch` / `@fetchAura` 占位符写在 `main` 内、编译前展开，
只保留 `contentTexel` / `auraTexel` 两个**单次采样**辅助函数。

### 🔧 斜面坐标修正：画面曾整体错位半个卡片

`BevelField.Evaluate(x, y)` 接收**卡片绝对坐标**（内部自己减半宽），CPU 侧传 `x + 0.5, y + 0.5`；
而 shader 传的是已经中心相对的 `p = rxy - h`，内部又减一次 `h`。整张法线/深度场因此偏移半个卡片，
渲染成**一片平涂 + 右下角一块折返的深色圆角矩形**。

改为 `bevelAt(rxy, h, radius)`；应用内诊断探针的同一处约定也一并修正——它当初是照着这个错误写的，
所以只能证明「画出了像素」，证明不了「画得对」。

**逐像素验证**（同帧 GPU vs CPU，`dist/glass-gpu-compare/`）：平均 \|Δ\| 从 **393.67** 降到
**23.13**（满分 1020），中心像素从 `#d7f3e2`（平涂薄荷色）回到 `#223629`（与 CPU 的 `#2a3e31` 一致）。

### 🧠 内存：桌面抓取不再按固定 3 秒宽限期堆积

每次采样都新建一张整个虚拟桌面物理分辨率的位图（2560×1440×4 ≈ 14 MB），旧的那张却要等
**3000 ms** 才释放——默认 10 fps 下**同时存活约 30 张 ≈ 420 MB**。这正是「液态玻璃内存占用极高」的主因。

`WallpaperSnapshot` 改为**引用计数**（新增 `WallpaperLease`），去掉定时器宽限期：谁在用就谁持有引用，
最后一个放手的瞬间释放。位图从位置参数改为 `init` 属性上的**租约引用**，`with` 复制的是租约而非裸位图
（否则副本会双重释放同一批像素）；预览用的 `with { Style, Tile }` 改走 `WithPlacement()`。

### 🛡 修复 GPU 路径启用后立刻出现的崩溃

开启 GPU 后应用以 `0xC0000005`（访问违规）崩溃，栈顶是 `SKBitmap.ToShader`。原因：Avalonia 会把
`ICustomDrawOperation` 留在合成树里并在**之后的帧**重新调用，而原先只用一个 250 ms 延迟释放
「大概保证」位图还活着——这个保证不成立，队列里的绘制操作会指向已回收的位图。

`Prepared` 改为**引用计数**，两个绘制操作在构造时 `AddRef`、在 `ICustomDrawOperation.Dispose()` 中释放；
`RetirePrepared` 立即释放自身引用，**不再有任何定时器**。CPU 回退路径同样改走自定义绘制操作，
顺带**去掉了 CPU 材质的 PNG 编码/解码往返**（新增 `LiquidGlassRenderer.RenderBitmap`）。

### 📉 实测

同一套 8 个组件、液态玻璃 + 实时采样 100 ms：

| | 4 s | 8 s | 之后 |
|---|---|---|---|
| 修复前 | 468.8 MB | 591.1 MB | **崩溃** |
| 修复后 | — | — | 稳定 ~150–200 MB 工作集 / ~310 MB 私有，44 s 无异常 |

毛玻璃（Acrylic）基线 ~158 MB 工作集 / ~312 MB 私有——液态玻璃现已与基线持平。

### 🧪 回归

- 22 个测试套件中 **20 套全绿**；`MapAndTitleBarChecks`（2 项）与 `SingleInstanceChecks`（1 项）
  是既有失败（v1.9.8 上同样存在，与本次改动无关）；
- `GpuMaterialCheck` 新增内联器不变量与 `@fetch` 展开断言；
- `GlassGpuProbe` 真机 **0 失败**：crisp / soft+染色场 / soft 无染色场 / EdgeWidth=0 / 1×1 退化几何
  全部绘制成功，三个「必须为空」的反向对照如实返回全透明。

### ⚠️ 注意

`tests/` 在 `.gitignore` 中被忽略（`/tests/`），只有先入库的 21 个文件受版本控制。
**`tests/GlassGpuProbe` 目前未被跟踪**，但它是 GPU 路径唯一的真机验证手段，建议显式 `git add -f`。

设备端编译发生在**绘制时**，离线测试只能守住源码级不变量——改动着色器后请真机跑一次
`dotnet run --project tests/GlassGpuProbe`。

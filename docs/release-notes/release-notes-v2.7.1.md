## DeskCanvas v2.7.1 更新日志

> 两个"看得到摸不着"的老毛病根治：液态玻璃的模糊随"背景清晰度"悄悄衰减、右键菜单二级菜单点按钮后被强制压底；笔记组件的标题栏开关升级为三档可选。

---

### 🐛 1. 液态玻璃：同一"模糊"数值，清晰度越低模糊越弱

* **此前**：共享背景纹理在"背景清晰度"降采样后做模糊时，sigma 被预乘了一次清晰度系数——而 Skia 会把图像滤镜的 sigma 再乘一遍画布 CTM，等于模糊被平方缩放。25% 清晰度（出厂默认）下，同一模糊滑杆的实际视觉模糊只有 100% 清晰度时的约 **1/8**，滑杆手感随清晰度设置漂移。
* **现在**：模糊 sigma 以桌面像素为基准，由画布 CTM 一次性完成到纹理像素的换算；任意清晰度下同一模糊值的视觉模糊一致，且与 CPU 回退渲染路径（原分辨率、同公式）严格对齐。
* **回归检查**：`LiquidGlassChecks` 新增跨清晰度不变性检查（边缘 20–80% 过渡宽度在 100% 与 25% 清晰度下测得的桌面像素宽度须一致；旧代码 20.0 vs 2.4 px / 新代码 20.0 vs 22.2 px）。

### 🐛 2. 右键菜单"网格大小"二级菜单：点击按钮后被强制置底

* **此前**：组件窗口的 z 序带区矫正（`SetWindowPos(HWND_BOTTOM)`）没有带 `SWP_NOOWNERZORDER`，Win32 会把整个 owned 窗口组一起重新锚定——打开的右键菜单及其二级菜单正是组件窗口的 owned 弹窗。于是点一次列/行步进按钮（触发组件 resize 与矫正），菜单就被整组拖到"组件正上方"，视觉上沉到所有窗口之下。
* **现在**：带区矫正只移动组件窗口自身，owned 弹窗（右键菜单、二级菜单、下拉框）保持自己的 z 序不动。矫正只把窗口向下压，"owned 必须在 owner 之上"的不变量不受影响；二级面板（同一矫正路径）的同类隐患一并修掉。

### ✨ 3. 笔记组件：标题栏三选一（1.0.10）

* 组件设置里的"显示标题栏"开关升级为「**顶栏**」三选一：**顶栏与标题**（出厂外观）/ **仅顶栏**（保留彩色顶栏与展开按钮、不显示标题文字，顶栏保持 44px 高度不塌缩）/ **隐藏顶栏**（顶栏与分隔线整体收起、正文占满整卡，即原开关关闭的行为）。
* 旧配置无缝迁移：遗留的 `ShowTitle` 布尔键继续按原语义生效（false = 隐藏顶栏），设置页首次选择后自动把新旧两键写齐，互不打架。

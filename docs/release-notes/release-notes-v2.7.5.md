## DeskCanvas v2.7.5 更新日志

> 开关与选中态控件的单色配色根治（悬停变白、关掉单色后残留纯白两处根因）、组件库预览的内边距终于与桌面实物一致、组件右键菜单圆角 4 → 12px。

---

### 🐛 1. 开关/复选/单选配色根治：悬停变白、关掉单色后残留纯白

* **三个复现场景**：① 亮色模式鼠标悬停在打开的开关上，轨道与圆点全白看不见；② 暗色 + 黑白档下点"关闭黑白"，开关圆点由黑变白看不见；③ 接②再切亮色，开关仍然全白（哪怕没悬停），只有重新打开黑白才"恢复"。
* **根因一（场景②③）：强调色渐变会残留**。`SystemAccentColor` 等键写在 `Application.Resources` 里，**跨多次 `Apply` 存活**；旧代码只在「彩色 / 手选强调色 / 单色档」三条路径写它，其余情况**什么都不做**——而"什么都不做"等于保留上一次的值。于是关掉黑白档后 `SystemAccentColor` 停在黑白写下的纯白，而开关 ON 轨道的取色源 `SystemControlHighlightAccentBrush` 正是它：白轨道 + 白圆点。切亮色也没人再写这个键，所以只有重开黑白才会被改成黑色而"恢复"。
* **根因二（场景①）：Fluent 的 hover/pressed 接了会翻转极性的键**。Fluent 把 `ToggleSwitchFillOnPointerOver` / `Pressed` 硬接在 `SystemAccentColorLight1` / `Dark1` 上，而本应用的渐变是**交叉写入**的（`Dark*` 供亮色字典读、`Light*` 供暗色字典读）。于是 Fluent 眼里的"亮一点的强调色"在单色档下恰好是对侧极性的纯色——悬停一下轨道就跳成与圆点同色（亮色黑白：黑轨道 hover 变白，白圆点也是白）。
* **修复**：`ThemeService` 的强调色解析收敛成**唯一一个 switch**，每条分支要么重写整套渐变、要么**交还 Fluent**（新增 `ClearAccentOverrides()`，未手选强调色时移除自己的覆写，让系统强调色重新生效），渐变再也不会残留；`Accent.axaml` 把 ON 轨道的 hover/pressed 钉回 `SystemAccentColor`，只用透明度做深浅反馈——任何强调色、任何极性都不会撞色。同族的复选/单选选中底色（`CheckBoxCheckBackgroundFill*`、`RadioButtonOuterEllipseChecked*`）一并修复。
* **回归**：`MonochromeAccentChecks` 新增断言——单色关闭后整个渐变覆写必须移除且轨道不再残留纯白、hover/pressed 在四档单色态下必须与圆点对比色不同。回退源码改动后这 18 项全部失败（正好覆盖上述三个场景），修复后全部通过。

### 🐛 2. 组件库预览与桌面实物对齐（内边距）

* **预览跑的是真实组件控件，但内边距是猜的**：预览侧硬编码 `Margin 12`，而桌面宿主的真实规则是——组件自己在 XAML 根节点写的 `Margin` 优先（本地值压过样式），没写的才由宿主补 12px，`Flush` / `Frameless` 归零。
* **影响面 14/30**：自带 `Margin="0"`（画面满铺到卡片边缘）的组件——笔记、音乐、搜索、待办、天气、地图、文件夹、相框等——在组件库里被**多缩进了 12px**；笔记的彩色标题条从满铺变成四边内缩最明显。此外 `Note` 的 `Flush` 类是由宿主按类型名补上的，预览根本看不到，所以判定也救不回来。
* **修复**：内边距规则上移到 `App.axaml`（`.widget-content-host`），桌面卡片 `Border` 与组件库预览框带**同一个类**、走**同一条规则**，组件自己写的 `Margin` 依旧优先——两边不可能再算出不同的内边距；宿主的类标记抽成 `WidgetContentHost.Prepare()`，桌面与预览两条宿主路径共用；删除预览侧硬编码的 `ContentMargin`。
* **验证**：`SettingsProbe` 新增组件库探针，逐个断言预览里控件的真实 `Margin`（覆盖三档：自带非零 / 自带 0 / 未写靠宿主兜底 12），全部一致；同时输出笔记预览的实拍图对照。

### 🐛 3. 组件右键菜单圆角 4 → 12px

* 外壳与菜单项悬停高亮保持**同一圆度**（两者圆度不一致时，5px 内边距下悬停高亮的方角会贴着外壳弧线，看着像两个互不相干的形状；两种方案都做了渲染比对）。
* 注意这是**三处同步**：`App.axaml`（全局样式）、`Widget.axaml`（组件窗口级样式，对组件菜单优先级更高）、以及 `Widget.axaml.cs` 的 `ContextMenuCornerRadius` 常量——该常量驱动菜单的 `Clip` 与毛玻璃弹窗的原生窗口区域裁剪，**只改样式不改它，菜单会被裁回旧圆角**。

## uWidgetsPlus v1.9.9 更新日志

> 核心是把「柔光玻璃」并入「液态玻璃」成为**单一主题**，并把逐像素光学从 CPU 搬到 GPU，
> 配合**实时桌面采样**以兼容动态壁纸。

### ✨ 主题合并：柔光玻璃 → 液态玻璃

柔光玻璃不再是一个并列主题，两者本就是同一条管线、同一种表面。合并后仍然只有一个「液态玻璃」主题：

- **默认观感不变**：液态玻璃预设回到出厂清脆配方，老配置升级后渲染结果与 v1.9.8 一致；
- **老柔光用户无损迁移**：`NormalizeMaterial()` 在折并表面时**原样保留光学参数**，
  迁移后依然渲染成柔光观感；
- **柔光配方改用旋钮选择**：新增的「柔光晕 / 光谱弥散 / 染色扩散」三行现在属于合并后的主题，
  鼠标一抬即从清脆切到柔光，不必再切换主题；
- 预设由 5 个减为 4 个（毛玻璃 / 纯色 / 液态玻璃 / 多彩）；
- 无边框时钟 `ThemeMode = 2`（强制液态玻璃）现在会同时清零柔光配料，否则合并后无法真正"强制清脆"。

### ⚡ GPU 光学管线（CPU 只负责一次降采样 + 模糊）

CPU 逐像素渲染一张 1200×800 的卡约 **110 ms**——作为「算一次缓存起来」的静态材质够用，
实时采样下完全不可行。现在：

- **CPU**：每次采样只做一次「降采样 + 模糊」，得到一张**所有组件共享**的背景纹理（引用计数管理）；
- **GPU**：整个光学模型（月牙透镜位移、色散、七抽头光谱、染色晕染、鲜度/霜度、
  边缘描边 + 镜面高光 + 环境光泽、柔光晕）移植到 SkSL，在渲染线程求值；
- **CPU 渲染器完整保留**作为回退。

### 📡 实时采样与动态壁纸

- **采样源支持动画壁纸**：此前只抓 `Progman`，而壁纸引擎根本不画进 Progman，
  「兼容动态壁纸」实际没被满足。现在按 **WorkerW 链**（Wallpaper Engine 桌面模式）→ `Progman` → 静态文件逐级回退；
- **采样间隔下限 3 ms**（默认 100 ms）。含义是「不再由间隔决定速度」：
  采样是**需求驱动**的——tick 只请求新帧，真正的抓取发生在上一帧被消费并渲染之后；
- **没人看就不采样**：没有可见的玻璃表面或全屏覆盖时自动停止；
- **关闭开关 = 冻结当前帧**（仍允许一次采样，避免回落到静态壁纸文件）。

### 🛡 设备端自检与自动降级

Skia 的 runtime shader 在**绘制时**才编译设备端程序，且要降级成 **ES2 兼容方言**——
比 `SKRuntimeEffect.Create` 接受的方言窄得多。**失败时不报错，只是什么都不画**（卡片全透明），
而本机光栅后端一绘制就崩，所以这条路径**离线无法验证**。

因此在第一次 GPU 绘制时做一次**自检**：把材质渲染到离屏表面并读回中心像素，
全透明则判定设备端不可用，**永久切回 CPU 渲染器并重新渲染**。用户拿到的始终是**可用的玻璃**，
而不是一张空白卡片。

### 🔧 其他修复

- 实时采样 tick 不再作废在飞的渲染（此前每次采样都会把已完成的帧判为过期丢弃）；
- GPU 准备不再被 CPU 渲染的并发信号量饿死（此前第 3 个之后的组件永远拿不到材质）；
- 着色器坐标空间换算：画布是 DIP、光学模型是渲染像素，**125% 缩放下圆角与透镜会整体错位**；
- 「对齐偏移」不再被重复应用一次。

### ⚠️ 已知问题（请务必留意）

- **GPU 路径目前在本机不可用**：设备端编译失败（已排除 `out` 参数等构造，
  把七抽头光谱与手写双线性都拿掉后仍然不可见），因此**实际渲染走的是 CPU 回退**。
  自检会记录到 `%LocalAppData%\uWidgets\glass-debug.log`；
  在 GPU 可用的机器上会自动使用 GPU 路径，无需设置。
- 走 CPU 回退时，实时采样的上限就是 CPU 渲染速度（大卡约 30–160 ms），
  动态壁纸下更新率会明显低于 GPU 路径；静态壁纸则完全不受影响。
- 排查用的痕量日志固定写在 `%LocalAppData%\uWidgets\glass-debug.log`（上限 800 行）。

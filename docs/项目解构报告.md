## 1. 项目定位

uWidgets 是常驻 Windows 桌面的信息小组件宿主：把时钟、日历、天气、系统监控、便签、提醒、文件夹
快捷方式、音乐控制、搜索、剪贴板、翻译、地图、图片、番茄钟、进度、电池、固定看板与重叠容器等
**17 个插件**以半透明 macOS 风格卡片固定在桌面上，并提供网格吸附、多屏独立布局、配置方案切换与
整机备份。

应用**没有主窗口**：进程只创建桌面组件窗口，唯一的常驻入口是通知区托盘图标
（`Services/TrayIconService.cs`，可在自身菜单里隐藏，组件右键菜单可再打开）。设置窗口是全进程
唯一的 DI 单例且关闭时只隐藏，因此「退出」必须经 `Services/AppShutdown.cs` 统一宣告。

单文件模式把全部插件 DLL 与默认配置以 `EmbeddedResource` 打进 exe，运行时解压到
`%LocalAppData%\uWidgets\`，因此插件在目标机上仍是普通磁盘文件，可单个替换热更新。
入口为 `src/uWidgets/Program.cs`（WinExe + `StartWithClassicDesktopLifetime`）。
界面语言只保留简体中文（默认）与英语，资源在 `src/uWidgets/Locales/Locale.resx`
与 `Locale.zh-Hans.resx`；每个插件自带 `Locales/Locale.resx` + `Locale.Designer.cs`。

### 2.2 DI 容器

容器在 `App.OnFrameworkInitializationCompleted()`（`src/uWidgets/App.axaml.cs`）一次性装配，全部为
单例；插件类型经 `ActivatorUtilities.CreateInstance` 从同一容器取构造参数。

| 注册项 | 实现 | 职责 |
|---|---|---|
| `IAppSettingsProvider` / `ILayoutProvider` | `Core/Services/AppSettingsProvider` / `LayoutProvider` | `appSettings.json` / `layout.json` 读写与归一化 |
| `IAssemblyProvider` | `Core/Services/AssemblyProvider` | 插件发现 / 加载 / 反射激活 |
| `IThemeService` / `ILocaleService` | `Services/ThemeService` / `LocaleService` | 主题解析与样式字典切换 / 界面语言 |
| `IGridService<Widget>` | `Services/GridService` | 网格吸附与尺寸 |
| `IWidgetFactory<Window, UserControl>` | `Services/WidgetFactory` | 组件窗口创建与生命周期 |
| `ProfileService` | `Services/ProfileService` | 配置方案增删改查与切换 |
| `DisplayMonitorService` | 同名 | 显示器枚举、身份匹配、热插拔 |
| `FullscreenWatcherService` | 同名 | 全屏/最大化覆盖检测 |
| `WallpaperThemeService` / `WallpaperWatcherService` | 同名 | 壁纸明暗判定 / 壁纸变更事件 |
| `MemoryTrimmerService` / `UpdateService` | 同名 | 长会话内存平整 / GitHub Release 更新 |
| `Settings` + `Func<Settings>` | `Views/Settings` | 全进程唯一的设置窗口 |

启动编排有一处刻意安排：先创建不可见锚窗口 `Views/WidgetAnchorWindow` 并
`displayMonitor.Attach(anchor)`，**刷新屏幕列表之后**才建组件，保证只为真实接入的屏幕建窗；
随后挂 `ScreensChanged`（热插拔）与 `FullscreenChanged`（挂起/恢复）。

### 2.3 插件加载机制

`Core/Services/AssemblyProvider.cs`：

- **发现**：扫描 `Widgets\*.dll`，`IsPotentialWidgetAssembly` 先按文件名排除框架与依赖
  （`lib*`、`av_*`、`Microsoft.*`、`System.*`、`WinRT.*`、`TimeZone*`、`Markdig.dll`、
  `uWidgets.Core.dll`）。
- **读元数据**：候选 DLL 在临时 `PluginLoadContext` 中加载，读 `WidgetInfoAttribute`
  （视图/模型/设置类型、标题资源键、默认跨度）与 `LocaleAttribute`（显示名、SVG path data）；
  无 `WidgetInfo` 的丢弃。结果按程序集名缓存为 `ILookup`。
- **激活**：`LoadAssembly(name)` 取同名最高版本，在**专属**可回收 `PluginLoadContext` 中加载；
  `Activate(type, args)` 依次尝试 `ActivatorUtilities.CreateInstance` → `Activator.CreateInstance`
  → 手工按构造参数逐个从 args / 容器 / 默认值凑齐。
- **依赖解析**：`PluginLoadContext.Load` 优先复用默认上下文里已加载的同名程序集（Avalonia / Core
  由宿主提供），其次 `AssemblyDependencyResolver`（各插件 `*.deps.json`），最后探测插件同目录同名 DLL。
- `UnloadAssembly(name)` 走可回收上下文的 `Unload()`。

> ⚠️ 组件类型完全靠反射激活，**发布时绝不能开启 Trimming**（`PublishTrimmed`）。

## 4. 关键流程

### 4.1 启动

```
Program.Main
 ├─ SingleInstance.Acquire()          命名内核对象；非首个实例 → Signal() 后退出
 ├─ SyncRunOnStartup()                按偏好重写注册表自启项（best-effort）
 ├─ BuildAvaloniaApp()                Win32 + WinUIComposition；
 │                                    WinUICompositionBackdropCornerRadius = WindowCornerRadius
 └─ StartWithClassicDesktopLifetime(args)
     └─ App.OnFrameworkInitializationCompleted()
         ├─ WidgetBundle.ExtractIfNeeded()   先备好数据目录（见 §4.5）
         ├─ 构建 DI 容器 → localeService.SetCulture → themeService.Apply
         ├─ UpdateCornerRadiusResources；Resources["SettingsWindowCornerRadius"] = WindowCornerRadius
         ├─ 全局 ContextMenu 钩子：禁用 DWM 外边框
         ├─ profileService.EnsureSeeded()
         ├─ 锚窗口 + displayMonitor.Attach + ScreensChanged / FullscreenChanged 回调
         ├─ widgetFactory.Create() → 逐个 Show()
         ├─ SingleInstance.Listen(显示设置窗口)；TrayIconService.Start()
         ├─ 无组件 或 args[0] == "--settings" → 打开设置窗口
         └─ UpdateService.CheckForUpdates()；MemoryTrimmerService.Start() + 6 秒后一次整理
```

单实例（`Services/SingleInstance.cs`）用命名内核对象：第二个实例先
`InteropService.AllowOtherProcessToTakeForeground()` 再 `Signal()`，运行中的实例收到后把共享
设置窗口 `ShowAndActivate()`。未捕获异常写入 `Const.DataFolder\crash_log.txt` 后重新抛出。

### 4.2 插件发现与激活

`WidgetFactory.CreateInternal` → `assemblyProvider.LoadAssembly(layout.Type)` →
`GetWidgetInfo(assembly, layout.SubType)`（在程序集上按 `ViewType.Name == SubType` 精确匹配
`WidgetInfoAttribute`）→ `CreateWidgetControl` → `assemblyProvider.Activate`。

`CreateWidgetControl` 只按需注入两样：视图构造函数若声明 `IWidgetLayoutProvider` 就传入，以及模型
实例（`WidgetLayout.GetModel(ModelType)` 反序列化 `Settings`）。设置面板同理，`EditModelViewType`
非空时才创建 `EditWidget` 对话框。

### 4.3 组件创建与布局

`Services/WidgetFactory.cs` 维护 `Dictionary<screenId, List<Widget>>`：

| 方法 | 用途 |
|---|---|
| `Create()` | 为每个已接入且**有配置**的屏幕建组件；先 `MigrateLegacyWidgets()` |
| `Add(screen, layout)` | 追加组件到指定屏配置（不存在则 upsert） |
| `CreateControl(type)` | 只创建内容控件（组件库预览） |
| `CloseScreen(id)` / `CloseAll()` | 屏幕拔出 / 切换配置方案时关闭 |
| `CreateFromLayout()` | `Refresh()` 屏幕后重新建窗并 `Show()` |
| `SuspendAll()` / `ResumeAll()` | 全屏覆盖时挂起/恢复（不隐藏窗口） |
| `OnScreensChanged()` | 热插拔：无主屏幕关窗，新屏幕按磁盘配置重建 |
| `SetWidgetsHidden(bool)` | 托盘「隐藏组件」（只切可见性，不动计时器） |

`Views/Widget.axaml.cs`（1,651 行）是单个组件窗口的全部行为：拖动、缩放、右键菜单（尺寸矩阵 /
内容缩放 / 主题 / 编辑 / 移除 / 配置方案）、跨度解析、原生窗口区域裁剪、材质缓存释放，以及把位置
尺寸写回 `IWidgetLayoutProvider`。

### 4.4 设置与持久化

数据提供者是一对泛型 JSON 读写器（`Core/Services/JsonParser.cs`）：`Get()` 首次读盘并
`Normalize`，`Save()` 先触发 `DataChanging`、写盘、再触发 `DataChanged`（携带 old/new）。
`AppSettingsProvider.Normalize` 做 `SurfaceThemes` 键的大小写无关规整、把旧 `SoftGlow` 表面并入
`LiquidGlass`、为当前表面补主题快照、`Grid` 为空时填 `Grid.Default`，并把
`(int)GridMode == 1` 归一化为 `Manual`。`LayoutProvider.Get` 先按 `ScreensLayout` 反序列化，
遇 `JsonException` 说明是 v1 扁平 `WidgetLayout[]`，用 `ScreensLayout.FromLegacy` 包成单个
`primary` 条目；`Normalize` 强制 `Version = 2`，最后 `Deduplicate()` 清重复空屏条目。

`WidgetLayoutProvider`（每组件一个）是**受约束的写入者**：`Save` 只更新
`WidgetLayout.IndexOfIdentity` 找到的既有条目，找不到就丢弃并记 Debug 日志——「布局拥有组件集合，
组件只能更新自己那条」。这是切换配置方案时不串档的结构保证。

### 4.5 单文件打包与数据目录双模式

`Core/Const.cs` 在类型初始化时决定数据目录：

| 模式 | 判定 | 数据位置 |
|---|---|---|
| 便携 | exe 旁存在 `Widgets\` 目录 | exe 所在目录 |
| 打包 | 无 `Widgets\` 目录 | `%LocalAppData%\uWidgets\` |

`Program.Main` 最先调用 `Services/WidgetBundle.ExtractIfNeeded()`：① `appSettings.json` /
`layout.json` 缺失时从内嵌资源写出（**不覆盖**用户已有文件）；② 便携模式且 `Widgets\` 已存在则返回；
③ 否则算内嵌 `uWidgets.Resources.widgets.zip` 的 **SHA-256**，与 `Widgets\.version` 比对，不同才
删除并重新解压（带路径穿越防护）。标记是**内容哈希**而非版本号，所以任何插件 DLL 变化都会触发
重解压；同时 `%LocalAppData%\uWidgets\Widgets\` 下的 DLL 可直接替换、重启即生效（热更新）。

## 5. 配置体系

### 5.1 文件与位置

| 文件 | 类型 | 说明 |
|---|---|---|
| `appSettings.json` | `AppSettings` | 全局设置 |
| `layout.json` | `ScreensLayout` | 每屏组件布局（v2；v1 扁平数组仍可读） |
| `Profiles\<名称>.json` | `BackupData` | 配置方案快照（与备份同格式） |
| `Widgets\.version` | 文本 | 插件包内容哈希标记 |
| `crash_log.txt` | 文本 | 未捕获异常（仅崩溃时生成） |

### 5.2 `AppSettings`

| 字段 | 类型 | 语义 |
|---|---|---|
| `Theme` | `Theme` | 当前生效主题 |
| `Templates` | `Theme[]` | 主题模板数组（默认文件给 2 项）；外观页实际渲染 `AppearanceViewModel.SurfaceTemplates` 里硬编码的 4 个表面预设 |
| `SurfaceThemes` | `Dictionary<string, Theme>?` | 按 `SurfaceStyle` 名索引的**每表面独立主题**，键大小写无关；缺键时 `GetThemeForSurface` 给内置预设 |
| `Layout` | `Layout` | `GridMode` / `SnapSize` / `LockSize` / `SnapPosition` / `LockPosition` |
| `Dimensions` | `Dimensions` | `Size`（1×1 虚拟单位像素，默认 72）、`Margin`（16）、`Radius`（24） |
| `Grid` | `Grid?` | 全局手动网格（`Manual` 模式兜底；为空取 `Grid.Default`） |
| `Region` | `Region` | `Language`：`zh-Hans` / `en` |
| `RunOnStartup` / `IgnoreUpdate` | `bool` / `string?` | 注册表自启项 / 忽略的版本号 |
| `UpdateUrl` | `string?` | 自定义更新源；空 → `DefaultReleaseApiUrl` |
| `HttpProxy` | `string?` | `null`/空 = 直连，`"system"` = 系统代理，其他 = 代理 URL（`Core/Services/ProxySettings.cs`） |
| `TitleBarStyle` / `TitleBarSize` | `TitleBarStyle?` / `double?` | 设置窗口标题栏（`Native` 默认 / 红绿灯）与红绿灯直径（`null` → 12） |
| `ActiveProfile` | `string?` | 当前方案名，空 → `DefaultProfileName`（"默认配置"） |
| `ShowTrayIcon` | `bool` | 默认 `true`，托盘与组件右键菜单都可切换 |
| `UpdateInterval` / `LastUpdateCheckTime` | `UpdateCheckInterval` / `DateTime?` | 默认 `Daily` / UTC |

> 内容缩放不在 `Dimensions` 里：它是 `ScreenLayout.ContentScale`（每屏）与
> `WidgetLayout.ContentScale`（每组件，优先），`null` → 1.0。

### 5.3 `Theme` 与表面材质

`Theme` 记录含 `DarkMode`（`null` = 跟随系统）、`AccentColor`（`null` = 系统强调色）、
`OpacityLevel`、`Monochrome` + `MonochromeVariant`、`UseNativeFrame`、`FontFamily`、`Surface`、
`OutlineColor` / `OutlineWidth`（毛玻璃高光描边）、`SolidBackgroundDark` / `SolidBackgroundLight`、
`AutoTheme`、`LiquidGlass`。

| 值 | `SurfaceStyle` | 含义 |
|---|---|---|
| 0 | `Acrylic` | 毛玻璃：OS 级实时模糊（DWM 逐帧采样桌面合成） |
| 1 | `Solid` | 纯色：逐像素透明的实心卡片，颜色与不透明度可调 |
| 2 | `LiquidGlass` | 液态玻璃：应用自绘壁纸折射材质（已吸收柔光配方） |
| 3 | `OutlinedAcrylic` | 描边毛玻璃：兼容保留值，描边已是毛玻璃自身的选项（`OutlineWidth > 0`） |
| 4 | `Colorful` | 多彩：macOS 扁平鲜艳风格，丰富语义色 |
| 5 | `SoftGlow` | 柔光玻璃：兼容保留值，由 `LiquidGlass` 的 `Glow` / `Spectrum` 表达 |

派生判定：`EffectiveSurface`（旧配置可从 `OpacityLevel` 回推）、`IsGlass`、`IsLiquidGlass`、
`UsesRenderedGlass`、`UsesNativeBlur`、`IsColorful`、`IsSoftGlow`、`EffectiveLiquidGlass`
（经 `Normalize()` 钳制）、`NormalizeMaterial()`（把 `SoftGlow` 折叠成 `LiquidGlass` 并保留光学参数）。

### 5.4 `LiquidGlassSettings`

材质光学的唯一参数源，全部经 `Normalize()` 做有限性与范围钳制（默认值即出厂配方，对齐作者调校的重模糊/强色散静态方案）：

| 参数 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `Blur` | 100 | 0–100 | 背景模糊强度（渲染器映射为高斯 σ） |
| `Refraction` | 50 | 0–100 | 透镜位移强度 |
| `EdgeWidth` | 10 | 0–80 DIP | 透镜带宽度；0 = 完全关掉透镜环 |
| `Highlight` | 50 | 0–100 | 亮边线 + 镜面强度 |
| `Dispersion` | 100 | 0–100 | 色散强度 |
| `LightAngle` | 225 | 0–360° | 光照方向（225 = 左上） |
| `EdgeTint` | 25 | 0–100 | 边缘染色强度 |
| `WallpaperOffsetX/Y` | 0 | ±1000 DIP | 壁纸对准手工微调 |
| `Glow` / `Spectrum` | 0 / 0 | 0–100 | 柔光晕 / 七段光谱弥散（任一 > 0 即进入柔光配方） |
| `DyeSpread` | 0 | 0–100 | 染色向内扩散程度（0 = 染色只留在最外圈） |
| `LiveSampling` | false | — | 是否持续采样壁纸（默认静态，冻结最后一帧） |
| `LiveSamplingInterval` | 5 ms | 3–1000 ms | 采样目标间隔（帧被丢弃而非排队） |
| `BackdropClarity` | 25% | 25–100% | 共享背景纹理相对桌面长边的分辨率 |

设置页的外观光学区块（实时采样 → 染色扩散）默认折叠，标题只显示「液态玻璃」。

`IsSoftRecipe => Glow > 0 || Spectrum > 0`；`SoftGlowPreset` 保留柔光配方的一组工厂参数。

### 5.5 布局格式 v2

```jsonc
{ "Version": 2,
  "Screens": [{
    "Id": "primary",                  // 稳定 id；"primary" = 兼容旧版的默认条目
```

才丢弃，两块真实孪生屏各自保留布局）。

### 5.6 配置方案与备份

`Services/ProfileService.cs` 把「整套设置 + 所有屏幕布局」快照成
`BackupData(CurrentVersion: 2, AppSettings, Screens)` JSON：

- `EnsureSeeded()`：目录不存在则建；无方案或当前方案文件缺失时写入当前状态。
- `SwitchProfile(name)`：保存当前方案 → **先拆掉现有组件窗口** → 读目标方案 → 保存设置与布局 →
  `displayMonitor.Refresh()` → 应用语言与主题 → `CreateFromLayout()` → 触发事件 → 延迟一次内存整理。
- `Create` / `Duplicate` / `Rename` / `DeleteProfile`：名字经 `SanitizeProfileName` 过滤非法字符；
  不能删当前方案，也不能删到只剩零个。
- `ExportProfile` / `ImportProfile`：文件拷出/拷入，导入名冲突时追加 `_1`、`_2`…

「先 `widgetFactory.CloseAll()` 再换布局」是硬约束：仍存活的组件窗口会一直持有布局订阅，先换布局
就会把旧条目写回新布局。`CloseAll` 内部 `PrepareForTeardown()` → `Hide()` → `Close()`，先停订阅
再关窗，避免新旧两组组件同屏闪烁。`Services/BackupService.cs` 负责完整备份与单屏导出（同一结构），
`Services/AppRestart.cs` 在导入等必须重启才生效的场景重启进程。

## 6. 网格与布局引擎

### 6.1 网格模式

| 值 | `GridMode` | 行为 |
|---|---|---|
| 0 | `Manual`（默认） | 桌面划为 m×n 正方形格子；组件尺寸 = 跨度 × 格子，位置强制吸附 |
| 1 | `Virtual` | 已废弃（`[Obsolete]`）；读取时归一化为 `Manual` |
| 2 | `Free` | 无网格，自由定位与缩放（预设跨度 80 px/单位） |

外观页与**全屏网格编辑器**（`Views/GridEditor.axaml.cs`）共同编辑 `Grid`：拖动网格区域整体移动、
右键弹面板改行列数与格边，变更实时保存；编辑器用 `InteropService.SetWindowPosition` 按物理像素
精确定位到目标屏（支持混合 DPI 与负坐标）。

### 6.2 百分比存储与 `GridMetrics`

| 字段 | 参照 | 说明 |
|---|---|---|
| `Columns` / `Rows` | — | 列数 n / 行数 m |
| `XPercent` | 工作区**宽度** | 网格区域左上角 X |
| `YPercent` | 工作区**高度** | 网格顶部线位置 |
| `CellPercent` | 工作区**宽度** | 格子边长；纵向沿用横向像素值，故格子恒为正方形 |

`GridMetrics.Resolve(grid, originX, originY, width, height)` 返回 `(Cell, X, Y)`，返回前
`Math.Max(cell, 8)` 兜底；`Grid.Default = (8, 6, 30, 10, 5)`。

### 6.3 DIP 与物理像素

`Services/GridService.cs` 区分两套单位：**尺寸用 DIP**
（`格子 DIP = GridMetrics.cell / screen.Scaling`，`window.Width = columns × cell`）；
**位置用物理像素**（`SnapPosition` 直接对 `window.Position` 取模吸附，随后 `ClampToGrid` 把整卡
收进网格区域：`min(max(position, origin), origin + extent - size)`）。网格来源按
**当前屏幕配置的 `Grid` → `AppSettings.Grid` → `Grid.Default`** 解析
（`GridService.GetGrid` 经 `displayMonitor.Find(window)?.Config?.Grid`）。

### 6.4 跨度与尺寸档位

组件跨度以「列,行」矩阵表达（1×1 … 4×4 及任意矩形），右键菜单写入 `Widget.ResizeSize`，
`Widget.CurrentSpan` 反解当前跨度。固定类组件实现 `IFixedSizeWidget`：只接受 `AllowedBaseSpans`
的整数倍，`SnapSpan` 就近取整（`Fixed` 聚合看板基跨度为 4×2，可见 4×2 / 6×3 / 8×4 / 10×5 …）。
`Services/SizeTiers.cs` 把跨度映射为内容档位供插件视图选布局——`Cell` = 1×1、`Small` = 2×2、
`Medium` = ≥3 宽 × 2 高、`Large` = ≥3 × ≥3、`Other` = 其余（2×1、1×2、2×3…）；档位按**网格跨度**
而非像素判定（格子像素因人而异），宿主不存在时（组件库预览）退回以 `CellSide = 100` DIP、
`WideRatio = 1.5` 为界的像素近似。

### 6.5 多屏

`Services/DisplayMonitorService.cs` 是屏幕身份与匹配的唯一来源：

- **身份**：`ScreenIdentity(DeviceName, FriendlyName, Width, Height, IsPrimary, Scaling)`，自动匹配键
  `Key = "FriendlyName|WidthxHeight"`；设备名与 EDID 名经 `EnumDisplayDevices` /
  `EnumDisplaySettings` 读取，与 Avalonia 屏幕按分辨率配对。
- **匹配优先级**（`ScreenMatcher.Match`）：① 手工绑定 `DeviceName` → ② 身份 `Key` → ③ 旧版
  `primary` 条目（`Key == null`，跟随当前主屏）。匹配是**消费式**的：一条配置最多匹配一块屏，
  孪生屏（同 Key）不会共享同一条目。
- **变更检测**：1.5 秒轮询屏幕签名（几何 + 缩放 + 匹配到的配置 id），变化才触发 `ScreensChanged`；
  `Attached` 列表每次都刷新。
- **热插拔**：`WidgetFactory.OnScreensChanged` 关掉无主屏幕的窗口、为新屏幕按磁盘配置重建；
  布局始终留在磁盘，重新插入即原位恢复。
- **旧版迁移**：`MigrateLegacyWidgets()`（幂等）把 `primary` 条目里中心点落在**其他**已接入屏幕
  工作区的组件搬到该屏自己的条目，并把绝对坐标转为相对该屏工作区的坐标，使每屏的网格与缩放
  作用于各自的组件。

## 7. 材质与主题系统

### 7.1 `ThemeService` 与样式字典

`Services/ThemeService.cs` 在设置变化（`DataChanging`）或壁纸明暗变化（`DarkFlagChanged`，仅自动
主题）时重建外观：① `RequestedThemeVariant`——自动主题用壁纸亮度判定，否则用 `DarkMode`
（`null` → `Default` 跟随系统）；② 写入资源 `FontFamily`（`"Inter"` → 内嵌
`avares://Avalonia.Fonts.Inter#Inter`）、`BackgroundOpacity`（多彩恒为 1.0）、
`SolidBackgroundDark` / `SolidBackgroundLight`（多彩固定 `#1C1C1E` / `#FFFFFF`）；
③ 按 `SwitchStyle(style, enable)` 增删 `Styles/*.axaml`：

| 样式字典 | 装载条件 |
|---|---|
| `Accent.axaml` | **总是**（强调色前景 / 组件标题 / 图标底色） |
| `MonochromeBlackWhite.axaml` | `!IsColorful && Monochrome && 变体 == BlackWhite` |
| `Monochrome.axaml` | `!IsColorful && Monochrome && 变体 != BlackWhite` |
| `Transparent.axaml` | `UsesNativeBlur && !IsColorful`（毛玻璃，OS 级模糊） |
| `Solid.axaml` | `!IsGlass && !IsColorful`（纯色） |
| `LiquidGlass.axaml` | `UsesRenderedGlass`（液态玻璃） |
| `Colorful.axaml` | `IsColorful`（最后加载，覆盖强调色回退） |

字体列表来自 `Services/SystemFonts.cs`：经 GDI `EnumFontFamiliesEx` 枚举系统字体族，把注册为独立
家族的粗细变体（如 "Arial Bold"）并入基础族，并附上捆绑的 Inter。`App.axaml` 另维护三个圆角资源
（`WidgetCardCornerRadius` / `WidgetInnerCornerRadius` / `WidgetPillCornerRadius`），由
`App.UpdateCornerRadiusResources` 按 `Dimensions.Radius` 派生（内层 = `0.70 × r`，
药丸 = `0.40 × r`，下限 2；原生边框模式为 0）；`Widget.UpdateAdaptiveRadiusResources` 允许单个
组件覆盖它们。

### 7.2 强调色（accent ramp）

`ThemeService.ApplyAccent` 会写入**整条** Fluent 强调色 ramp，而不只是 `SystemAccentColor`：
`Dark1/Dark2/Dark3` 与 `Light1/Light2/Light3` 六个 shade 键一并覆盖。

**为什么六个键都必须写**：Avalonia 的 Fluent 主题预先用自己固定的蓝色定义了这些键，因此**任何没被
写入的键都会保持 Fluent 蓝**。而浅色主题字典读 `SystemAccentColorDark1`（`Styles/Accent.axaml`
的 Default 字典），深色主题字典读 `SystemAccentColorLight2`（同文件的 Dark 字典）——漏写后者，用户
挑的颜色就只在浅色模式生效，深色模式仍是 Fluent 蓝。`Monochrome.axaml`、
`Views/Controls/ThemeButton` 以及配置方案徽标同样读这些 shade 键。

两种调用：用户选了颜色 → `ApplyAccent(color)`，base 与六个 shade **全部**写成该颜色本身（应用没有
自己的色阶层级，用户挑的颜色就该原样呈现）；多彩模式 → `ApplyAccent(#007AFF, light: #0A84FF)`，
即 `SystemAccentColor` 与 `Dark1–3`（浅色主题使用）= `#007AFF`、`Light1–3`（深色主题使用）
= `#0A84FF`，对应 Apple systemBlue 在两种模式下的取值。

**「跟随强调色」要读资源，不能只读 `Theme.AccentColor`**：`AccentColor == null` 表示「跟随系统强调
色」（默认），此时 `ApplyAccent` **根本不会被调用**，所以只看 `Theme.AccentColor` 的代码会落到自己
写死的蓝色上，无论用户实际强调色是什么。正确的两步解析是：① 用户手选的 `Theme.AccentColor` 优先；
② 否则取 `SystemAccentColor` 资源——手选颜色由 `ApplyAccent` 写在那里，跟随系统时则由 Avalonia 的
Fluent 主题用 OS 强调色种入同一个键（及其 shade ramp）。插件里的既有写法见
`Calendar/Views/Month.axaml.cs`、`Notes/Views/Note.axaml.cs`、`Fixed/ViewModels/AggregateViewModel`
与 `Clock/Views/FramelessDigital.axaml.cs` 的 `ResolveAccentColor`。

### 7.3 毛玻璃：OS 级实时模糊 + 原生区域裁剪

毛玻璃不使用应用自绘模糊，而依赖 DWM 合成器逐帧采样桌面：窗口声明
`TransparencyLevelHint="AcrylicBlur, None"`，动态壁纸因此实时跟手。代价是模糊覆盖整个 HWND，
所以要把原生窗口裁成卡片形状。`Views/Widget.axaml.cs` 的 `ApplyWidgetRegion()` 决定是否裁剪：
**只有毛玻璃需要**（`Theme.UsesNativeBlur`）——液态玻璃与纯色的透明边距与抗锯齿圆角走 32 位逐像素
alpha 合成，用 1 位 GDI 区域反而会把抗锯齿边缘切出锯齿；覆盖外层框架的组件（`IFramelessWidget`）
自行管理区域，外部一律不动；`UseNativeFrame` 为真时不裁剪（避免裁掉系统边框）。裁剪区域 = 客户区
减去 `Dimensions.Margin`、圆角取 `Dimensions.Radius`，经屏幕缩放换算为物理像素，区域相同时用
`lastAppliedRegion` 跳过重复设置；重叠容器带分页点时改用
`InteropService.SetWidgetRegionWithExtra`，把卡片圆角矩形与右侧点条 `CombineRgn(..., RGN_OR)`
求并集。

`InteropService` 的 Win32 封装：`CreateRoundRectRgn` / `CreateRectRgn` / `SetWindowRgn`（右/下边界
排他，统一 `+1`）、`ExtCreateRegion` + `RGNDATA` 扫描线（`SetWindowRegionFromSpans`，供无边框
时钟把模糊限制在字形轮廓内）、`SetWindowPos`（全屏覆盖层定位）、`DwmSetWindowAttribute`
（禁 DWM 外边框与圆角，用于右键菜单弹窗）、`SetProcessWorkingSetSize`（内存整理）。

### 7.4 液态玻璃：CPU 采样管线 + SkSL GPU 合成

液态玻璃是**应用自绘**材质：从桌面快照采样，按光学模型逐像素生成卡片背景位图。

| 组件 | 文件 | 职责 |
|---|---|---|
| 壁纸解析与采样 | `Services/LiquidGlassWallpaper.cs` | 首选 1:1 抓取真实合成桌面（`DesktopCapturer` + `PrintWindow(Progman)`），静态壁纸文件 + 注册表摆放规则作为回退；实时采样由 `DispatcherTimer` 驱动（3–1000 ms），按需抓帧（上一帧被消费并渲染后才抓下一帧）。该抓图缓存是进程内最大的单笔分配，`WidgetFactory.SuspendAll()` 会停止采样并 `Release()` 它，`ResumeAll()` 恢复采样、缓存随后台渲染重建 |
| 背景纹理缓存 | `Services/LiquidGlassSource.cs` | 按**引用**比较的快照身份 + 模糊/缩放参数，决定缓存的背景位图能否复用 |
| CPU 光学渲染 | `Services/LiquidGlassRenderer.cs`（1,133 行） | 圆角矩形距离场给出外向法线与内向深度，深度驱动三条叠加带：**透镜环**（`lensW` 宽、`bend = rim²` 向内位移、边缘放大中心清晰）、**边缘反射带**（约 `0.7 × 短边`、叠加 2× 位移，形成 iOS 药丸上下缘的倒影回声）、**边缘保护带**（最外几像素把位移收敛到 0，压噪点并制造折叠）。面部再叠 vibrancy（饱和度提升）、自适应霜化（暗背景抬亮，不是奶白填充）、1 px 均匀亮边线、方向性镜面/Fresnel、对角光泽带与背光侧内阴影；色散约为位移的 0.06 倍 |
| GPU 合成 | `Services/LiquidGlassGpuEffect.cs`（757 行） | 同一套光学模型写成 SkSL，由 Skia 运行时着色器在渲染线程求值；只有背景纹理在 CPU 上构建（每次抓帧一次降采样 + 一次模糊，所有组件共享） |
| 表面控件 | `Views/Controls/LiquidGlassSurface.cs`（959 行） | 只绘制背景的玻璃控件：GPU 可用即走着色器，否则回退 CPU；移动/缩放/调参时合并（debounce）渲染请求；静态 `RenderSlots = new SemaphoreSlim(2)` 限制并发材质数；持有 GPU 可用性、首帧绘制、着色器回读、设备自检等一次性状态 |
| 二级面板 | `Views/SecondaryPanelWindow.cs` | 提醒、大文件夹、天气、剪贴板等弹窗的公共模板。**玻璃与一级组件完全同源**：卡片由同一个 `LiquidGlassSurface` 绘制，开合缩放逐帧把当前 scale 交给 `SetAnimationFrameScale` 重参数化光学 —— 实时采样开关只决定采样到的桌面帧是否继续刷新，不改变渲染路径 |
| 诊断 | `Services/GlassDiagnostics.cs` | 有上限的渲染决策轨迹（GPU 路径无法离线验证，"卡片空白"有多种成因） |

两条**改代码时必须守住**的后端约束（写在 `LiquidGlassGpuEffect` 的类型注释里）：
① `SkRuntimeEffect` 只在 Skia 的 GPU（Ganesh）后端可用，在栅格后端绘制会以不可捕获的
`SEHException` 终止进程，所以调用方必须先确认渲染租约真的持有 `GrContext`，
`LiquidGlassRenderer` 是始终可用的回退；② `sample()` 只能**词法上写在 `main` 内**——Skia 用入口点
的 `_input` 参数构造子着色器调用，一旦内联器拒绝内联某个采样辅助函数，生成程序就会在无该参数的
函数里引用 `_input`，设备端报 `unknown identifier '_input'` 并**什么都不画**（静默透明卡片）。
因此所有 `sample()` 由 `@fetch` 展开直接落在 `main` 里，单 tap 的 `contentTexel` / `auraTexel`
各只含一次 `sample()`；`GpuMaterialCheck` 会对展开后的源码断言这两条性质。

### 7.5 窗口圆角几何

`Program.WindowCornerRadius = 8`（DIP）是**应用自身窗口**的圆角常量，与 `Dimensions.Radius`
（组件**卡片**圆角，常被配到 36 之类的大值）是两件事。它同时供给两处，保证两侧永不漂移：
① `Win32PlatformOptions.WinUICompositionBackdropCornerRadius`（平台构建时读取一次，整个会话固定）；
② 资源 `SettingsWindowCornerRadius`（`App.OnFrameworkInitializationCompleted` 写入），由
`Views/Settings.axaml` 的根 `Border` 用 `CornerRadius` + `ClipToBounds` 裁剪自身玻璃面，使模糊背景
与 0.80 不透明度的着色共享同一条圆角轮廓。

**为什么是 8 而不是更大**：Windows 自己会给顶层窗口按显示器 DPI 缩放后加一圈抗锯齿圆角（基准
8 DIP）与配套阴影，且是加在**成品**窗口上（内容与合成背景一起）。因此 backdrop 半径只要**不大于**
那圈弧就不可见，窗口呈现一条干净圆角；一旦更大，就会在系统弧内再画第二条弧，两弧之间的细缝没有
玻璃（表现为「角落缺一小块」）。**为什么不用 `SetWindowRgn`**：该区域是 1 位掩码，用它裁窗口会让
圆角出现肉眼可见的锯齿（`SetWindowRgn` 只用于毛玻璃卡片与弹窗的**内容区域**裁剪，见 §7.3）。

### 7.6 桌面带内窗口的两个不变量（改 `WidgetZOrder` 前必读）

组件窗口与二级面板**都不是普通应用窗口**，它们靠两条原生窗口不变量维持观感，两条都必须在窗口的
**整个生命周期**内成立（`WidgetZOrder`）：

1. **无 owner 链**。Avalonia 会把 `ShowInTaskbar=false` 的窗口挂到它自己的屏幕外隐藏窗口上；带内窗口
   必须把这条 `GWL_HWNDPARENT` 切断，否则窗口管理器会把整组 owned 窗口重新锚定，两条带互相纠正、
   UI 线程空转（类型注释里的详细推演）。
2. **扩展样式恰好是「工具窗口」**：`WS_EX_TOOLWINDOW` 置位、`WS_EX_APPWINDOW` **必须清零**。切断 owner
   之后，任务栏按钮就只剩这一个开关；而 `APPWINDOW` 的优先级**高于** `TOOLWINDOW`，所以只要它被置位，
   TOOLWINDOW 再稳也会冒出按钮（Avalonia 每次重算样式都会按它缓存的 `ShowInTaskbar` 写这一位）。

Avalonia 会在 **每一次样式重算**（`ShowWindow`、窗口状态/装饰变更、透明级别切换……）里把这两条都改回去，
所以两处都必须自愈：样式位经 `Win32Properties.AddWindowStylesCallback` 在每次重算时强制回写并在改完后用
`SWP_FRAMECHANGED` 立即刷新（窗口管理器对可见窗口的扩展样式有缓存，不刷新就可能被资源管理器按旧值判定）；
owner 链与样式位则在既有的 `WM_WINDOWPOSCHANGED` 钩子里每次放置复核一次。症状就是"唤起二级面板时任务栏
闪现一下 uWidgetsPlus"——因此 `tests/BottomBandChecks` 把「该窗口是否会被资源管理器给出任务栏按钮」
写成了断言（可见 + 非工具窗口 + 无 owner 或带 APPWINDOW），并把 hide/show、透明级别、装饰、激活、
`ShowInTaskbar` 往返等重算路径全部走一遍。

### 7.7 全局文字阴影的作用域（`WidgetTextShadow`）

`外观 → 全局文字阴影`按**视觉根是否为组件窗口**（`VisualRoot is Views.Widget`）决定是否给文字加
`DropShadowEffect`；设置窗、对话框、二级面板、托盘菜单**明确排除**（它们保持系统清晰文字）。作用域由
代码实现而非全局样式，正是为了这条边界。

**两类文字宿主都要覆盖**：`TextBlock`（自绘文字）与 `TextPresenter`（`TextBox` 的文字——它不是
`TextBlock`）。只处理前者，就会让「可编辑标签」全部漏掉：待办清单的每一条是 `ClickThroughTextBox`，
所以清单标题/计数有阴影而**具体事项没有**。新增文字宿主时（例如自定义文字控件）必须同步登记到
`WidgetTextShadow.Install` 的两条 class handler 里。

## 8. 小组件模块

每个模块的 `AssemblyInfo.cs` 用 `[WidgetInfo(视图, 模型, 设置视图, 标题键, 副标题键,
defaultColumns, defaultRows)]` 注册，`[Locale(..., 图标 path data)]` 提供显示名与图标。
共 **17 个模块 / 32 个可放置视图**；括号内版本号取自各模块的 `AssemblyInfo.cs`。

**Clock**（v1.2.6，6 视图）— 模拟 I/II/III、数字、世界时钟、无边框数字。前四者共用 `ClockModel`；
`WorldClockModel(TimeZoneIds, CityNames)` 支持多表盘与自定义城市名（时区换算用 `TimeZoneNames`）。
无边框时钟最重：`Views/FramelessDigital.axaml.cs`（≈40 KB）把数字拉伸铺满整格，
`Services/GlyphLiquidGlassRenderer.cs` 对字形掩码做欧氏距离场（EDT）求法线、把玻璃光学画进笔画内部，
`Services/FramelessThemeResolver.cs` 把**全局主题**映射为当前帧的三种渲染分支：毛玻璃（扫描线区域把
模糊限制在字形内）/ 液态玻璃 / 纯色。无边框时钟**没有任何组件级材质或光学覆盖**——历史设置项已全部
删除，残留值被反序列化直接忽略：

- `ThemeMode`（曾把液态玻璃与柔光玻璃列为两个独立材质）随二者合并而删除；柔光观感改由**全局**液态
  玻璃的「柔光晕 / 光谱弥散」两个光学参数表达；
- `DyeIntensity`（边缘染色强度）删除，字形玻璃与毛玻璃高光描边都直接读全局的
  `LiquidGlassSettings.EdgeTint`；
- `RefractionWidth`（边缘折射宽度）删除，字形透镜一律走由全局 `EdgeWidth` / `Refraction` 推导的
  **自适应镜头**（`ResolveLens` 的 `null` 分支）。

`GlyphLiquidGlassRenderer.ResolveLens` 仍保留显式 `refractionWidth` 参数，但只服务于光学检查工程里
的镜头宽度扫描，生产路径只传 `null`。

**字形距离场必须精确且用上抗锯齿覆盖率**（`GlyphLiquidGlassRenderer.ComputeDistanceField`）：整个材质
（透镜位移、亮边线、边缘染色、方向性镜面）都读这个场，而亮边线只有约 1.5 px 宽。旧的 3×3 棋盘扫描把
距离量化成 1 / √2，**量化误差还随局部边缘走向变化**（水平边 ~1 px、45° 边 ~1.414 px），斜边于是逐像素
交替，亮边线被调制成虚线——这就是「毛刺边 / 断断续续」。现在用精确欧氏距离变换（Felzenszwalb &
Huttenlocher 可分离下包络，O(n)）+ 覆盖率亚像素修正（抗锯齿像素直接给出轮廓在像素内的位置），
对解析圆测近场轮廓误差从 0.399 px 降到 0.145 px、抗锯齿边界像素 0.032 px；`tests/ClockGlassChecks`
把旧算法在测试内原样重算作为对照，并断言新场至少把误差减半。

**字体粗细是一条轴，不是一个 OpenType 请求**（`FramelessDigital.ResolveWeightedTypeface`）：
`FramelessClockModel.FontWeight`（100–900）现在表示**滑轨位置**。参考字重（700，组件默认）及以下由字体
家族**真实字面**回答，观感与历史完全一致；参考字重以上按位置合成加粗（笔宽 = 比例 × 0.06 em 描边并与
填充取并集），所以 700→900 对**每一种**字体都有效。这条是必需的：精选字体多为单字面（华为锁屏超窄体
只有一个 Black、Impact 只有一个 Regular），旧九档下拉在这类字体上九档全部落到同一字面、设置完全无效；
默认 Inter 的最大字面是 Bold，最高两档同样是死的。`tests/ClockVisualChecks` 用真实渲染的墨迹面积断言
这一点（单一字面家族 700→900 必须变粗，默认家族 100→700 也要变粗）。

## 9. 构建与发布

```powershell
dotnet build src\uWidgets.sln -c Debug                    # 开发构建（全部工程）
powershell -ExecutionPolicy Bypass -File .\build.ps1       # 单 exe → dist\win-x64\uWidgets.exe
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Runtime win-arm64
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Configuration Debug
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Portable   # 额外产出便携布局 + zip
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Msi         # → dist\installer\...msi
```

`build.ps1` 的步骤：先结束正在运行的 `uWidgets` 进程（避免占用输出文件）→
`dotnet publish -r <rid> --self-contained false` 到 `dist\<rid>` → 删掉散落的 `.pdb` / `.xml` /
`appSettings.json` / `layout.json` / `icon.ico`（保证 dist 里只有 exe）→ 可选便携布局与 zip →
可选 MSI。MSI 版本号由脚本从 `src\uWidgets\AssemblyInfo.cs` 读出并回写 `installer\Package.wxs`，
因此安装包不可能滞后于应用版本（`Package.wxs` 里的字面值只是上一次同步的结果）。

`src/uWidgets/uWidgets.csproj` 的关键属性：`PublishSingleFile`、`PublishReadyToRun`、
`IncludeNativeLibrariesForSelfExtract`（Avalonia 原生库随 exe 打包，运行时自解压到临时目录）、
`GenerateAssemblyInfo=false`（版本号来自手写 `AssemblyInfo.cs`）、Workstation GC +
`ConcurrentGarbageCollection` + `RetainVM=false`。MSBuild 目标 `BuildWidgetsBundle`
（`BeforeTargets="AssignTargetPaths"`，条件为「有 RID + Release + 非插件包递归 + 非设计时 +
非 VS 内构建」）执行：① `scripts/build-widgets-bundle.ps1` 逐个 `dotnet publish` 全部插件到**同一个
扁平** staging 目录（`/p:BuildingWidgetBundle=true` 防递归），删除 `*.pdb` / `*.xml` /
`*.runtimeconfig.json`，保留各插件的 `*.deps.json`；② `Compress-Archive` 打成
`obj\widgets-bundle\widgets.zip`；③ 作为 `EmbeddedResource` 以逻辑名
`uWidgets.Resources.widgets.zip` 嵌入 exe。`appSettings.json` 与 `layout.json` 同样以
`uWidgets.Resources.*` 逻辑名内嵌，由 `WidgetBundle.ExtractIfNeeded()` 首次运行时写出（§4.5）。

包版本集中在 `Directory.Packages.props`（CPM，`ManagePackageVersionsCentrally=true`），应用与所有
插件共用同一 Avalonia 版本，各 `.csproj` 的 `PackageReference` 一律不写 `Version`。当前：
Avalonia 11.1.3 全家桶、SkiaSharp 2.88.8、Microsoft.Extensions.DependencyInjection 8.0.0/8.0.1、
Microsoft.Win32.SystemEvents 8.0.0、System.Management 8.0.0、TimeZoneNames 6.0.0、Markdig 0.34.0。
应用版本 = `src/uWidgets/AssemblyInfo.cs` 的 `AssemblyVersion`（也是 MSI 版本来源）；插件版本在各模块
自己的 `AssemblyInfo.cs`。新增插件：复制 `src/Widgets/Clock/` 骨架 → 改 `[WidgetInfo]` / `[Locale]`
→ `dotnet sln add` → 重新构建（打包脚本遍历 `src/Widgets` 下每个目录，自动发现新模块）。
`AVLN3001`（XAML 资源无公开构造函数）在宿主与多数插件经
`<NoWarn>$(NoWarn);AVLN3001</NoWarn>` 抑制——这些视图都由代码 / `DataTemplate` 实例化，从不经
运行时 XAML 加载器解析；`Music` 额外抑制 `CA1416`。`src\uWidgets.sln` 当前以 **0 错误 / 0 警告** 构建。

> ⚠️ **不要开启 `PublishTrimmed`**：插件类型靠反射激活，裁剪会破坏整个插件机制。

## 10. 测试与验证体系

`tests/` 下是 **28 个独立可执行程序**，不是单元测试框架：每个工程是 `OutputType=Exe` 的 `net8.0`
控制台程序，以断言打印 + 生成对照图的方式验证，失败即返回非零退出码。

```powershell
dotnet run --project tests/<名称> -c Release -- <输出目录>
```

多数检查把 PNG / CSV 写到 `--` 后的目录（约定 `dist/<名称>/`）便于人工比对。这些工程通过
`<Compile Include="../../src/..." Link="..."/>` **直接编译**被测源文件，或 `ProjectReference`
引用 `uWidgets.Core` 与插件工程，因此验证的是真实实现而不是副本。

| 检查工程 | 覆盖内容 |
|---|---|
| `LiquidGlassChecks` | 液态玻璃主检查：配置兼容、参数保存与范围、圆角、模糊、折射、高光、色散、移动取样、纯色桌面回退、极端尺寸。含 4 个子模块：`OpticsProfile`（把「好不好看」变成可断言数字：透镜剖面、肩部峰值、放大率、二阶差分、圆角与中轴线法线连续性、渲染像素与生产位移公式的偏差、亮边线峰值/FWHM/截白比例、vibrancy 与自适应霜化、色散集中度、性能预算）、`SoftGlowProfile`（柔光配方：边缘染色归属、`EdgeWidth = 0` 时折射必须完全失效、染色扩散的内向衰减与过渡宽度、光晕单调性与可见宽度、光谱重加权、色散集中度）、`GpuMaterialCheck`（GPU 材质源码级断言：禁止的 SkSL 构造、`sample()` 必须在 `main` 内、单 tap 辅助函数、uniform 必须有限、几何单位守卫——背景缩放不得移动采样原点）、`WallpaperLayoutCheck`（用真实壁纸判定实际摆放规则与生产帧的端到端一致性）。产出 `liquid-glass-preview.png`、`liquid-glass-real.png`、`optics-profile.png`、`optics-displacement.csv` |
| `GlassGpuProbe` | **真机逐像素对比**：驱动真实 ANGLE/EGL 窗口绘制 GPU 材质并回读像素，与 CPU 渲染器同帧对比（`Compare`）；`Perf` 分解一个采样回合的成本（桌面抓取 ~20 ms，`PrintWindow` **不能**渲染到更小的目标只能裁剪，降采样 + 模糊是主要可变成本）；`Probe` 是 GPU 材质在设备端的验收测试 |
| `ClockGlassChecks` | 驱动真实 `GlyphLiquidGlassRenderer`（组件同款字形掩码：文字 → 拉伸几何 → 光栅化 alpha），把字形轮廓「毛刺/断裂」这类主观缺陷变成可比对数字，输出掩码、锐利背景、玻璃结果与放大边缘。含两项针对性检查：**距离场精度**（解析圆上测 `ComputeDepthField` 的近场误差/抖动，并把旧的棋盘扫描算法在测试内原样重算作对照，断言新场至少把误差减半——现为 0.399 → 0.145 px，抗锯齿边界像素 0.032 px）与**斜边亮边连续性**（45° 笔画的两条长边定深采样，量高频能量与亮暗跳变，断言亮边不是虚线） |
| `TextShadowChecks` | 全局文字阴影的**覆盖范围**：同一根下 `TextBlock` 与可编辑标签（`TextBox` 的 `TextPresenter`）都必须拿到阴影且共用同一个 effect 实例，加强度必须真的改变 effect 参数，关闭必须两个宿主都清干净（回归「清单标题有阴影、具体事项没有」） |
| `ClockThemeChecks` | 无边框时钟的**全局材质解析**（`FramelessThemeResolver` 纯函数：毛玻璃 / 纯色 / 多彩 / 液态玻璃 / 已存柔光玻璃 / 合并后的柔光配方 / 无主题回退）与「模型不再带 `ThemeMode` / `DyeIntensity` / `RefractionWidth`、残留值可安全反序列化」；第一部分验证该类型确能经 `ActivatorUtilities.CreateInstance` 由 `WidgetFactory` 激活并拿到 `IAppSettingsProvider`，第二部分渲染全局液态玻璃 vs 全局毛玻璃两版快照做逐像素比对，末段验证「跟随强调色」的两步解析（手选色 → `SystemAccentColor` 资源 → 遮罩不透明度） |
| `ClockVisualChecks` | 无边框时钟在精选艺术字体与各大跨度下的渲染快照（固定 `SystemAccentColor` 以便覆盖「跟随强调色」的遮罩用例），并断言**字体粗细轴的墨迹面积**：单一字面家族（华为超窄体）700→900 必须变粗、默认家族 100→700 也必须变粗——把"设置无效"变成可比对数字 |
| `BottomBandChecks` | 桌面 z 序带（`WidgetZOrder`）：组件永久置底、二级面板只置于组件带之上、无组件存活时回退到底部，激活 / 重新显示 / 原生 `SetWindowPos(HWND_TOP)` 都必须被幂等修正；并断言带内窗口**不会被资源管理器给出任务栏按钮**（可见 + 非工具窗口 + 无 owner 或带 `APPWINDOW`），把 hide/show、透明级别切换、装饰变更、激活、`ShowInTaskbar` 往返等"重算样式"路径全部走一遍（见 §7.6） |
| `ScreenIdentityChecks` | 屏幕身份硬化（防远程控制虚拟屏"收留"已存配置）：EDID 硬件 ID 钉住的条目只匹配该物理屏、匿名屏不得按名称/分辨率认领配置、陈旧的匿名条目被清理、真实命名屏照旧精确匹配 |
| `SettingsLifecycleChecks` | 设置窗口生命周期（UU 远程会话事故回归）：虚拟屏增删会让设置窗口在一段时间内无组件可依，共享单例**永不真正关闭**、只隐藏，任何组件状态下关闭/重开都不得崩在 `ShowAndActivate` |
| `RemindersUnifiedSourceChecks` | 待办清单统一数据源（`RemindersStore`）：多视图 / 多屏共享同一份模型，跨视图改动必须同步、且不得回流成自激更新 |
| `CalendarHollowChecks` | 日历（`Month`）与聚合看板内日历（`AggregateView`）「当日数字镂空」的像素验证：数字内部必须透明、圆盘仍填配置色 |

**验证方法上的硬规则**（写在 `GpuMaterialCheck` 与 `GlassGpuProbe.Compare` 的注释里）：分辨率、缩放
这类几何参数必须用「**同一桌面点在任意缩放下的采样坐标是否一致**」来验证，而不是看渲染结果
「像不像」——光滑的合成测试图对位置类错误天然不敏感，参考壁纸因此改用 40 px 高频网格，并按
100% / 50% / 25% 三档背景清晰度分别比对。同样地，GPU 路径**无法离线验证**（栅格后端绘制运行时
着色器会终止进程），所以「只在设备端成立」的性质被拆成两半：能在源码层面锁死的写成
`GpuMaterialCheck` 的文本断言，只能在设备上确认的交给 `GlassGpuProbe` 的真实窗口回读。
